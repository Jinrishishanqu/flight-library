# 飞行图书馆 · 项目说明

> 本地私有的中文成人同人文库：采集 → 排版 → 校勘 → 入库 → 检索与阅读 → AI 补全，
> 全流程可在单机离线复现。本文是总纲，细节各自指向 `文档\` 下的专题文档。
>
> 当前规模：**464 部作品 · 3,403 节 · 1,793.7 万字 · 2,759 张角色卡 · 13 个原作分族**
> （另有 22 部已并入主本的副本不计入可见书目）

---

## 一、这是什么

### 1.1 要解决的问题

网上流传的 H 同人文有三个顽固毛病：

1. **文本脏** —— 盗版站水印（`SIS001`、`本文由XX整理`）、拼音打码（`肉w棒`、`乳#头`）、
   全角数字（`３Ｐ`、`１００`）、形近错字（`闻然→闻言`、`猛得→猛地`）、
   专名前后不一（`薰儿/熏儿/萧黛儿`）。
2. **排版烂** —— 整本压成一两段，章标题和正文粘在同一行，一句话被硬切成两半。
3. **散** —— 同一部书有十几个版本散在十几个文件里，各有删节与补写；续篇和原作者无关，
   却顶着同一个书名。

本项目做的事就是把这三件事逐层解决，并把结果装进一个能长期积累、能检索、能读的库。

### 1.2 内容边界

全部内容为成人向同人小说（原作涉及斗破苍穹、斗罗大陆、大主宰、武动乾坤、神印王座、
凡人修仙传、诛仙、元尊、仙逆、遮天、完美世界、神墓、不死不灭）。**仅本地私有，
不出网、不分发、不对外提供服务。** 阅读站只监听 `127.0.0.1`。

### 1.3 当前状态

| 指标 | 数值 | 说明 |
|---|---|---|
| 原文文件 | 748 个 txt | `原文\`，采集后冻结，字节不动 |
| 排版稿 | 491 个 | `校对后文章\`，S1 层 |
| 成品 | 486 个 | `校勘版\`，S2+S3+S4 层 |
| 可见作品 | 464 部 | 库里 `merged_into IS NULL` 的部分 |
| 已合并副本 | 22 部 | 内容被主本覆盖，只留 `merged_into` 指向 |
| 章节 | 3,403 节 | 其中 1,921 节用的是原文自带的真章标题 |
| 正文字数 | 17,936,855 | 只算正文，不含章标题 |
| 角色卡 | 2,759 张 | 每部 ≤50 张，按作品隔离，AI 生成小传 100% 覆盖 |
| 标签 | 43 个 | 题材/玩法/关系向 |

## 二、目录与数据分层

### 2.1 根目录

```
飞行图书馆\
├─ 原文\            源库（S0）：采集后冻结，永不修改
├─ 校对后文章\      排版层（S1）：只动换行与编码
├─ 校勘版\          成品层（S2+S3+S4）← 交付用
├─ 采集工具\        全部脚本
│  ├─ 词库\         词典知识库
│  ├─ 校勘\         校勘层脚本
│  ├─ 书库\         SQLite 库 + 本地阅读站
│  ├─ py\           排版层与校验的 Python 实现
│  └─ 记录\         运行台账（CSV）
├─ agent\           流水线执行器（脚本调度 + AI 走 API）
├─ 文档\            规则、调研、报告
├─ 站点\            静态记录站（数据看板，与阅读站无关）
├─ 归档\            备份与中间产物，可整体删除
├─ .venv\           Python 3.12
├─ 起飞！.cmd        阅读站入口
└─ README.md
```

**根目录只放正式产出与入口。** 一次性脚本、临时输出、调试数据一律进
`归档\临时文件\<日期>\`，规则见 `归档\README.md`。

### 2.2 语料三层与四道工序

| 层 | 目录 | 做什么 | 铁律 | 校验方式 |
|---|---|---|---|---|
| S0 源 | `原文\` | 无 | 采集后冻结，只增不改 | 文件数量只增 |
| S1 排版 | `校对后文章\` | 编码归一、换行、分段 | **一个字不改** | 去掉空白后字符序列与原文完全一致 |
| S2 净化 | `校勘版\` | 水印、打码、专名、形近字、全角残留 | 有据才改，改动留台账 | 逐层计数 + 抽样上下文核验 |
| S3 体例 | `校勘版\` | 引号、破折号、省略号、成人语汇、可读性重排 | 保留作者笔法，不统一浪叫 | 全库符号普查 |
| S4 结构 | `校勘版\` | 章标题独立、超长章切分 | 切点只在句末与对话边界 | 章节划分报告 |

三层职责严格分离，越往下改动越大，任何一层都能独立回滚：

- 删掉 `校勘版\` → 回到排版层，`校对后文章\` 不受影响
- 删掉 `校对后文章\` → 用 `原文\` 重跑 `py\build.py` 再生

### 2.3 目录即作品

`原文\` / `校对后文章\` / `校勘版\` 的子目录一律是**具体作品**，不允许「辰东」这种
作者合集目录。现有 13 个分族 + 一个 `待归类\` 兜底：

斗破 · 斗罗 · 大主宰 · 武动乾坤 · 神印王座 · 凡人修仙传 · 诛仙 · 元尊 · 仙逆 · 遮天 · 完美世界 · 神墓 · 不死不灭

判不出原作的作品进 `待归类\`，库里的 `source_work` 为空、`genre` 记「原创」。
归类脚本：`classify_source.py`（内容关键词 + 人工 `OVERRIDE` 表）与
`update_source_works.py`（同步库里的 `source_work` 与 `path_*`）。

> 教训：作品名作关键词必须要求出现在文件名或多次出现。`遮天` 会命中书名里的
> 「只手遮天」，`完美世界` 会命中纯原创的挂名同人。这两类都写进了 `OVERRIDE`。

## 三、流水线

### 3.1 全景

```
                 ┌──────────────────────────────────────────┐
 抓取 ──→ 原文\ ──┤ ①搜集/入库 ②校对(S1) ③校勘(S2/S3) ④校验  │──→ 校勘版\
                 └──────────────────────────────────────────┘
                                    │
                    ⑤build_db ──→ library.db ──→ 阅读站 127.0.0.1:8770
                                    │
                    ⑥章节/角色/索引/AI 补全（可由 agent 统一调度）
```

两种跑法：
- **手工**：直接调 `采集工具\` 里的脚本（每个都能独立运行）
- **agent**：`python -m agent run <pipeline>`，统一处理顺序、幂等、记账与门禁

### 3.2 采集

| 脚本 | 作用 |
|---|---|
| `采集工具\搜集.ps1` | 按 `sources.psd1` 的源与检索词抓取，落到 `原文\` |
| `采集工具\整合.ps1` | 把同一部书的散件按 `整合计划.psd1` / `families.psd1` 拼成一本 |
| `采集工具\入库.ps1` | 抽正文、去广告、编码归一后放进 `原文\` |
| `采集工具\查重.ps1` / `重叠检测.ps1` / `重叠合并.ps1` | 5-gram Jaccard 与字级重叠对齐 |
| `采集工具\OCR.ps1` / `截图.ps1` | 图片源转文本 |
| `采集工具\run-all.ps1` | 抓取→入库→校对→校验 一条龙 |

### 3.3 排版层（S1）

`采集工具\校对.ps1` → `采集工具\py\normalize.py` + `py\build.py`。

只做四件事：编码归一（utf-8 无 BOM）、段落分行、去掉行内多余空白、
章标题独立成行。**不做任何字词替换**，所以「去掉空白后与原文逐字相同」是可验证的硬约束。

规则全文见 `文档\校对规则.md`。

### 3.4 校勘层（S2 + S3 + S4）

按固定顺序跑，顺序本身是规格的一部分：

| 顺序 | 脚本 | 做什么 |
|---|---|---|
| 1 | `校勘\clean1.py` | 广告水印、竖线方框、拼音打码、HTML 实体 |
| 2 | `校勘\clean2.py` | 域名、分页残留、省略号归一 |
| 3 | `校勘\clean3.py` | NFKC 归一化与域名二次清理 |
| 4 | `校勘\unified3.py` | 统一体例 |
| 5 | `校勘\postprocess.py` | 后处理修补 |
| 6 | `校勘\final_polish.py` | 汉字间空格、错别字对 |
| 7 | `校勘\reflow.py` | 超长段按句末标点切分，**可逆**（删掉全部换行后与输入逐字相同） |
| 8 | `校勘\fix_glyph.py` | 形近错字（`闻然→闻言`、`猛得→猛地`、`白勺→的`） |
| 9 | `校勘\fix_numbers.py` | 全角数字转半角、拆散数字串 |
| 10 | `校勘\fix_orphan_bracket.py` | 行内栈式配对，删孤立 `【】` |
| 11 | `校勘\fix_wide_ascii.py` | 全角字母数字串转半角（`３Ｐ→3P`、`Ｇ点→G点`） |
| 12 | `校勘\fix_fullwidth_quotes.py` | 全角双引号 `＂` 按**栈**配对转 `「」`（不做交替） |
| 13 | `校勘\normalize_sex_style.py` | 成人语汇与符号风格统一 |
| 14 | `校勘\restore_chapter_titles.py` | 章标题从正文里剥出来独立成行 |

配套体检脚本（只报告不改）：`probe_encoding.py`（编码判决）、`scan_mojibake.py`（乱码）、
`confusable_scan.py`（UTS #39 同形字）、`clean_text.py`（ftfy 封装，`check` / `apply`）。

**校勘的判定顺序**（写死在词库 README 里）：

```
打码还原 → guard 保护 → confusion 替换 → 断词还原 → 符号统一 → 台账
```

`guard.txt` 保护 104 个专名正写（`萧薰儿`、`美杜莎`、`牧尘`…）。
频次只能发现候选，裁定权永远在原文与外部权威，所以 `confusion.txt` 每一行都带来源与裁定理由。

细节见 `文档\校勘报告.md`。

### 3.5 入库、章节与检索

| 脚本 | 作用 |
|---|---|
| `书库\build_db.py` | 从 `校勘版\` 全量建库：works / chapters / FTS / tags / fingerprints |
| `书库\rebuild_chapters.py` | 只重切 `chapters`，不动 works 与 characters（`--dry` 出报告） |
| `书库\refresh_fts.py` | 重算 `body_bi` 并重灌 FTS（改完库必须跑） |
| `书库\check_db.py` | 一致性体检（`--fix-chars` 统一字数口径） |
| `书库\dedupe_chapters.py` | 章节级重复检测与删除 |
| `书库\build_characters.py` | 角色识别与建档（hanlp + 出场范围评分） |
| `书库\merge_works3.py` | 同作异本合并（整块落位，不按章号散插） |
| `书库\import_chapter.py` | 新章节归户（sha256 / 开篇指纹 / 书名 / 角色共现四路打分） |
| `书库\backup_db.py` | `VACUUM INTO` 快照到 `归档\数据库备份\` |

**章节划分**是本项目最容易出错的一环，规则如下：

1. 原文有「第N章 / 第N回 / 第N卷 / 序章 / 楔子 / 番外」等行首标记 → 用真标题
2. 标记覆盖不完整时走 `partial` 模式：有标记处用真标题，洞里按字数切
3. 完全无标记 → 按 6,000 字切节，标题写 `第N节`、`is_real_title=0`
4. **分卷结构不排序**：出现「第N卷」就认为卷内章号各自从 1 开始，原文顺序即正确
5. 章号乱序才尝试排序，排完若仍有回退就放弃（说明章号本身不可信）
6. 卷名行挂到下一节标题前（`第二卷天书和美人 · 第6章机智的水月`），章号回退时清空

> 踩过的坑：`CHAPTER_RE` 的行尾 `[^\r\n]{0,40}$` 在 CRLF 文件上永远失配，
> 导致全库章标记识别为 0 而**不报错**。已经踩了四次，现在一律写 `\r?$`。

### 3.6 角色档案

```
build_characters.py --limit 50
  ├─ hanlp 分词 + NER 出候选人名（`ner_hanlp.py`，结果缓存到 data\ner\）
  ├─ 三道门过滤：person_score ≥0.30 / head ≥0.30 / strong ≥0.04
  ├─ 四类清洗：泛称（师伯/掌门）、势力后缀（宗/门/峰）、子串污染（青云 ⊂ 青云门）、
  │            后缀归并（小凡 → 张小凡，长名次数 ≥2 倍才并）
  ├─ 按作品隔离：一部最多 50 张卡，绝不跨作品合并记录
  └─ 主角判定 score = 0.45·coverage + 0.30·log(1+mentions)/log(1+top)
                        + 0.20·spread + 0.05·chap_ratio
```

- `coverage` = 全文切 100 块，角色出现的块数占比（对应 Mendenhall 的特征曲线思想：
  主角「高而平」，配角「短而集中」）
- `spread` = (最后出场位置 − 第一次出场位置) / 全文长度
- 分级：`score ≥ 0.55` 主角，`≥ 0.26` 配角，更低的不建卡（宁少不滥）
- 性别优先取人工表 `采集工具\词库\原作信息.tsv`（151 个原作角色 + 32 条别名）

角色小传由 agent 的 `bio` 环节生成，明细见第四章。

### 3.7 书目治理

| 脚本 | 作用 |
|---|---|
| `fix_titles.py` | 书名去数字前缀、去「独立N篇」「合集」标记、中文数字规则 |
| `scan_similar.py` | 两两比对找「同作异名」候选（A/B/C 三级） |
| `compare_pair.py <id1> <id2>` | 并排打印两篇的标题/字数/开头/段级重合，人工定夺 |
| `char_overlap.py <id1> <id2>` | 8-gram 双向 containment，判「同文 / 子集 / 续篇」 |
| `trace_pair.py <id...>` | 打印开头与结尾，读交界处判断续篇 |
| `merge_works3.py` | 执行合并 |

**合并判据（按可靠性降序）**：

1. 全文 sha256 相同 → 必是同一份
2. 字符级 8-gram 双向 containment ≥0.85 → 同文（差异只是删节与分段）
3. 小的完整包含在大 的里面、独有段 ≤3 段 → 子集
4. **书名互相包含不算依据** —— 103 对里绝大多数是不同作品（`斗破苍穹` ⊂ `斗破苍穹之始于云岚`）
5. **「续 / 前 / 后 / 新」字眼必须读原文交界处**：字符互含 0.00 既可能是无关作品，
   也可能是接续处没有重合的真续章

实测结论（写进 `文档\阅读站说明.md`）：

- `27 冰灵族银宴` / `97 续-冰灵族银宴`：互含 0.0014，但结尾「…轰！」与开头「轰！伴随着…」
  无缝衔接 → **真续篇，全量追加**
- `21 南宫婉失身` / `22 续-`：互含 0.00，22 自述「本文基本上是整体重新架构」→ 不合并
- `167 / 175`：段级重合 0.88，独有段落是同一句话的两种人名写法（`萧黛儿` 是 `萧薰儿` 的
  场景性错字，已统一 295 处）→ **合并**

合并的插入方式是「首位交接、整块落位」：剔除头部与主本重合的节，剩余内容保持原序
整块插到交接点之后，前缀 `另版 · `（续篇 `续 · `）。**不按章号散插** —— 那样会把
一本书撕成碎片。

## 四、agent 框架

### 4.1 为什么要它

原先每个环节都是独立脚本，靠人记顺序、靠人判断该不该重跑。500 万字的量级下，这件事
有三个具体痛点：

1. **不知道哪一步跑过** —— 改了一个词库文件，哪些作品需要重跑校勘？没人说得清。
2. **AI 补全没有账** —— 2,759 条角色小传是谁、哪一版提示词、花了多少钱写的，查不到。
3. **AI 结果与入库混在一起** —— 模型写坏了直接落库，回头没法比对，也没法只重入不重算。

agent 就是把这三件事收进一个执行器。**它不替代 `采集工具\` 里的脚本**，只是给它们
一个统一的调度层：每个环节知道自己依赖谁、跳过条件是什么、产出必须满足什么。

**选型结论：自写，不引框架。** 实查过 Prefect 3.9.3 / Dagster 1.13.30 / LangGraph 1.2.22 /
Temporal / Luigi，它们解决的都不是这里的瓶颈：

| 需求 | 框架能给什么 | 本项目要什么 |
|---|---|---|
| 编排顺序 | 声明式 DAG | 按声明顺序 + needs，300 行够了 |
| 断点续跑 | task 结果缓存 | 幂等 key 必须由业务定义（作品 id + 提示词版本 + 模型 + 正文 sha） |
| 可观测 | UI / 事件流 | 「哪部作品花了多少钱、哪步失败了」—— 一张 SQLite 表更直接 |
| 状态搬运 | TypedDict / asset / IO manager | 流动的是**磁盘路径 + 库里一行**，进内存纯属搬运 |

LLM 层只用官方 `openai==3.51.0`（wheel 2.3MB、6 个直接依赖）。不引 LiteLLM（41MB，
花费统计在内存 map 里关进程就丢）、不引 Instructor（给交互式补全设计的 DSL）。

### 4.3 一次 run 的时序

```
python -m agent run ai bio
  │
  ├─ Runner.__init__        载入 config、打开 ledger
  ├─ start_run              写 runs 记录（pipeline=ai, status=running）
  ├─ order(stages, only)    按声明顺序取子集
  └─ 对每个环节：
       ├─ dedupe_key(ctx) = sha256(环节名 + 输入指纹 + 环节代码 hash + 模型名)[:32]
       ├─ ledger.hit_ok(key)?  → 是则标 skipped，不执行
       ├─ start_step         写 steps 记录（status=running）
       ├─ st.run(ctx)        真正干活
       ├─ st.check(ctx)      门禁：产出不达标就判这一环节失败
       └─ end_step           写 status / duration / detail / log_path
  ├─ end_run                写 status=ok|failed
  └─ 打印本次花费与累计花费
```

- 失败即停：某一环节抛异常就 `end_run(failed)` 后中断，不继续往下
- `--dry` 只打印计划，不写台账、不执行
- `--force` 忽略幂等，强制重跑

### 4.5 三种 kind 的判据

| kind | 判据 | 例子 |
|---|---|---|
| `script` | 换一批输入重跑，结果**确定** | 全角转半角、章号排序、MinHash 查重 |
| `ai` | 规则写不出，错了**人一眼能看出** | 角色小传、书籍简介 |
| `hybrid` | 规则能定位「哪里可能错」，但裁定不了「错没错」 | 形近字候选、文字复核 |

`text_proof` 是 hybrid 的样板：脚本先按「全角残留 / 重复标点 / 连续单字」筛出可疑章节，
只把这些送模型，模型报出的候选进 `state\reports\text_proof.tsv` 供人确认，**不回改正文**。

### 4.6 幂等 key

```
sha256( 环节名 + "|" + 输入指纹 + "|" + 环节源码 hash + "|" + 模型名 )[:32]
```

四段各自的用意：

- **环节名** —— 不同环节的 key 不可能撞
- **输入指纹** —— 由各环节自己定义。`bio` 是「缺 bio 的角色数 + 提示词版本」，
  `build_db` 是 `校勘版\` 全库的 400 个文件元数据摘要
- **环节源码 hash** —— 改了 `stages\ai.py` 就自动失效，不用手动清缓存
- **模型名** —— 换模型必然重算

判定只看 `steps.status='ok'`：失败或跳过的记录不构成「已经做过」的证据。

### 4.7 成本台账与熔断

四张表：

| 表 | 记什么 |
|---|---|
| `runs` | 每次运行：pipeline、状态、起止时间、参数 |
| `steps` | 每环节：幂等 key、状态、耗时、门禁结论、日志路径 |
| `ai_calls` | 每次模型调用：`tag`（`bio:443` / `proof:21457`）、模型、提示词版本、token、折合美元、是否成功、第几次尝试 |
| `artifacts` | 产出文件的路径与 sha256（溯源用） |

```powershell
python -m agent cost 10        # 最近 10 次运行各花了多少
```

```sql
-- 按业务标签归集花费（哪个环节最贵）
SELECT tag, COUNT(*), ROUND(SUM(cost_usd),4)
FROM ai_calls GROUP BY tag ORDER BY 3 DESC LIMIT 10;
```

`[llm].max_usd_per_run` 是单次运行的硬上限，超了抛 `BudgetExceeded` 并中断。
**熔断在记完账之后触发**，所以超支那一笔一定留痕。
失败的调用也记一条（token 记 0），否则重试率无从统计。

单价在 `config.toml` 里，换模型必须同步改 —— 台账存的是**当时**折算好的 `cost_usd`。

### 4.8 提示词

全部在 `agent\prompts\*.txt`，代码里没有内嵌字符串。

| 文件 | 用途 | 占位符 |
|---|---|---|
| `bio.system.txt` / `bio.user.txt` / `bio.block.txt` | 角色小传 | `{title}` `{blocks}` / `{name}` `{role}` `{gender}` `{mentions}` `{paras}` |
| `summary.system.txt` / `summary.user.txt` | 书籍简介 | `{title}` `{source_work}` `{chars}` `{head}` |
| `proof.system.txt` / `proof.user.txt` | 文字复核 | `{work_title}` `{title}` `{body}` |

**版本自动生效**：`core\prompts.py` 的 `version()` 取目录内全部 `.txt` 的内容哈希前 12 位，
它进 `ai_calls.prompt_ver` 与各 AI 环节的输入指纹。改任何一个字，幂等 key 就变，下次运行必然重跑。

> 以前的 `PROMPT_VER = "v1"` 是手写常量，忘了 bump 就会「改了提示词却被幂等跳过」——
> 这是最难查的一类 bug，已经彻底删掉。

### 4.9 生成与入库分离

AI 环节**只产出 JSON**，不碰数据库：

```
state\out\bio\w443.json          ← 生成
state\out\summary\w19.json
state\out\text_proof\c26072.json

python -m agent apply bio        ← 入库
python -m agent apply summary
python -m agent apply proof      ← 只汇总成 TSV 报告，不改正文
```

好处：模型写坏了可以只重入不重算；入库策略改了不用重新花钱；产物可 diff、可归档。

入库策略刻意保守：

- `bio` 只填 `bio IS NULL OR bio=''` 的行，已有内容绝不覆盖
- `summary` 写 `summary_ai`；标签**只在为空时**写（现有的 43 个标签是脚本 + 人工整理的成果）
- `proof` 只写 `agent\state\reports\text_proof.tsv`，六列：work_id / chapter_id / 标题 / 原文 / 建议 / 理由

### 4.10 加一个新环节

1. 在 `stages\library.py` / `canon.py` / `ai.py` 里定义 `Stage(name=..., kind=..., run=..., needs=[...])`
2. 加进 `stages\__init__.py` 的 `ALL` 列表
3. 写门禁 `check(ctx)` —— 返回 `(detail, ok, problems)`，`problems` 非空就判失败
4. AI 环节另需：把提示词放 `prompts\`，产物写 `state\out\<stage>\`

### 4.12 AI 接口怎么配

三种情况，改 `agent\config.toml` 的 `[llm]` 段：

**A. OpenAI 官方**
```toml
base_url = "https://api.openai.com/v1"
model = "gpt-4o-mini"
api_key_env = "OPENAI_API_KEY"      # setx OPENAI_API_KEY "sk-..."
price_in_per_mtok = 0.15
price_out_per_mtok = 0.60
json_mode = "json_schema"
```

**B. DeepSeek（当前使用）**
```toml
base_url = "https://api.deepseek.com/v1"
model = "deepseek-chat"
api_key = "sk-..."                   # 或走 api_key_env = "DEEPSEEK_API_KEY"
price_in_per_mtok = 0.28
price_out_per_mtok = 1.10
json_mode = "json_object"            # DeepSeek 不支持 json_schema，传了会 400
```

**C. 任何 OpenAI 兼容服务** —— 只改 `base_url` + `model` + 两个单价。

`json_mode` 三档：

| 值 | 行为 | 适用 |
|---|---|---|
| `json_schema` | `response_format={"type":"json_schema",...}`，服务端照 schema 生成 | OpenAI 及部分网关 |
| `json_object` | 只要求合法 JSON，schema 以文字塞进对话末尾 | **DeepSeek / 多数兼容服务** |
| `none` | 不设约束，纯靠 `parse_json` 剥围栏 | 调试用 |

> 实测：DeepSeek 传 `json_schema` 直接 `400 This response_format type is unavailable now`。
> `json_object` 档下模型仍能稳定输出合规 JSON（50 节抽样 495 处候选，0 次解析失败），
> 结构靠提示词 + 客户端 `parse_json` + 门禁三重兜底。

### 5.1 表

| 表 | 作用 |
|---|---|
| `works` | 32 列，一部作品一行 |
| `chapters` | 8 列，一节一行；`(work_id, idx)` 唯一 |
| `chapters_fts` | FTS5 contentless 虚表，正文与标题的 bigram 索引 |

### 5.2 `works` 关键字段

| 字段 | 说明 |
|---|---|
| `title` / `subtitle` / `author` | 书名已去数字前缀与合集标记；`author` 填充率低（原文基本不标） |

| `notes` | 事实性备注（如「分卷结构，卷内章号各自从 1 开始」「含 5 处私有区字符，源文件乱码不可逆」） |
| `path_source` / `path_proof` / `path_canon` | 三层路径（可多分卷，`\|` 分隔） |
| `merged_into` | 非空表示这部已被并入另一部，默认查询隐藏 |
| `char_count` / `chapter_count` / `reading_minutes` | 字数只算正文（不含章标题），时长按 400 字/分钟 |

### 5.3 `chapters` 与检索

- `title` 为空时用 `第N节` 占位，`is_real_title=0`
- 正文放 `content`，索引放 `body_bi`

**bigram 落库的原因**：FTS5 的 trigram 查不了 2 字词（`MATCH '薰儿'` 返回 0），
必须把中文切成相邻二字 token 存进 `body_bi`，查询侧同样 bigram 化并包成短语。

```python
TOKEN_RE = re.compile(r"[\u4e00-\u9fff]+|[A-Za-z0-9]+")
# 汉字串 → 相邻二字；字母数字串 → 整词小写（NTR / SM / 3P）
```

汉字串与字母数字串**必须分开取词**，否则「NTR情节」会变成一个既非 bigram 也非词的
token —— 曾经导致「22 章正文含 NTR 却只有 3 章能搜到」。

单字不进索引（每章都存会让 token 数翻倍），查询侧用前缀 `乳*`。

### 5.4 口径三条

1. **可见书目** = `merged_into IS NULL`。所有列表、统计、来源分布都要带这个条件，
   `?merged=1` 才能看到全部 486 部。
2. **字数** = `SUM(chapters.char_count)`，不含章标题。`check_db.py --fix-chars` 统一。
3. **章节总数** = 可见作品的 `chapters` 之和（3,403），不是表里的行数（3,499）。

## 九、已知限制

**文本层**

- **标点级残留**：125 部作品的 `chapters` 拼接比原文少 400–1,100 字（占 0.01–0.3%），
  来源是 `split_title` 的 `[：:、.．\s]*` 吃掉标题分隔符。不影响阅读与检索。
- **私有区乱码不可逆**：9 种 53 个字符，其中两处是整段（`斗破之掠美六界`、`遮天`）。
  `gbk` / `gb18030` / `big5` 反推全部失败，属源文件自带，只能保留并记入 `notes`。
- **404 部作品原文无完整章标记**，只能按字数切节（标题是 `第N节`）。
- **`series` 字段全空**：实测同一原作内不存在「公共前缀 ≥3 字的书名族」，判定为无此结构。

**元数据**

- `author` 填充率 23/464 —— 原文基本不标作者。
- `pairing` 352/464 —— 只统计得到前 3 名角色的性别。

**AI 层**

- `text_proof` 有误报：`企求 → 祈求`（企求也成立）、`一身心魂`（可能原文如此）。
  所以只出报告不改正文。

### 回滚

| 想撤销什么 | 怎么做 |
|---|---|
| 校勘层改动 | 删 `校勘版\`，从 `校对后文章\` 重跑 |
| 排版层改动 | 删 `校对后文章\`，从 `原文\` 重跑 `py\build.py` |
| 库的改动 | `copy 归档\数据库备份\library_before_<改动>_<stamp>.db data\library.db` |
| 某次合并 | `UPDATE works SET merged_into=NULL WHERE merged_into=<主本id>;` 再 `rebuild_chapters.py --apply` |
| 某批 AI 产物 | 删 `agent\state\out\<stage>\`，重新跑（幂等 key 会因产物消失而失效） |
| 提示词改动 | 直接改 `prompts\*.txt` —— 版本哈希自动变，下次运行必然重算 |
