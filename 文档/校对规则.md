# 文本格式校对规则

> 本文是 `校对.ps1` / `py\normalize.py` 的实现依据。项目整体结构与工作流见根 `README.md` 与 `文档\目录结构说明.md`。

本规则用于整理小说、番外和章节分卷。正文的文字、标点和先后顺序保持原样。校对范围为换行、空行、段落边界和 TXT 编码。结果另存到 `校对后文章`，沿用原有的分类子目录。

## 读取原文件

- TXT 按实际编码读取。本批次包含 UTF-8、GB18030 和带 BOM 的 UTF-16。读取时用严格解码，避免把无法识别的字节替换成乱码字符。
- DOCX 按正文顺序提取文字、段落和手动换行。输出为纯文本，Word 的字体、字号等版式随转换去除。
- ZIP 内文件与已解压文件逐一比较。本批次归档中的 409 份文件与目录里的对应文件逐字节一致，使用目录中的文件作为输入。

## 换行和段落

1. **接回固定行宽造成的断行。** 按每份原文统计常见行宽，计算时区分全角与半角字符。前一行接近反复出现的固定行宽，后一行无新段缩进，并且标点或上下文排版表明句子仍在继续时，将两行接回。即使前一行碰巧在句号处折行，也结合该文件的缩进规律判断。
2. **修复明显错断的标点和句子。** 相邻两行中，行首出现明显属于上一行的逗号、句号或右引号时，结合前一行判断是否接回。在整篇普遍隔一空行的文件里，也检查被空行隔开的断句。接回相邻的半角字母或数字时，用空格保留分隔。
3. **保留段落标记。** 章标题、序章、后记、分隔线及独立成行的省略号保留独立行。有明确首行缩进的段落优先保留。对原文里挤在同一长行的段落，仅在句末标点后的空格反复形成段落分隔规律时恢复分段。
4. **统一段间距。** 保留已有段落的首行缩进，清理行尾空白，段与段之间留一个空行。输出使用 Windows 的 CRLF 换行和带 BOM 的 UTF-8 编码。
5. **保留存疑的边界。** 某处换行缺少足够的排版线索时保留分段。原文已有的错字、缺文或乱码字符原样保留。

## 章节合并

- 用原文件名、正文章标题和明确的续篇标记确认作品身份及章节顺序。连续的文件按章号从小到大拼接，文件交界处留一个空行，保留原有章标题。例如，`1~3` 和 `4` 合并为 `1~4`。
- 正篇和续篇各自重新编号时，文件名保留两段编号，例如 `正篇1~11＋续篇1~8`。明确标为正篇和续篇但缺少原章号的，可以用 `1~2` 表示两个文件的顺序。
- 对章节有重叠的版本、同题异文和顺序无法确认的文件，分别保留。只有编号连续且归属明确的分篇才合并。合集内部的章节顺序沿用原文。
- 两篇章号错位但正文重复（作者重编号续写）时，先 `章对齐.ps1` 找出重复章，再由 `章拼接.ps1 -Plan` 按剧情顺序取章：重复章保留字数更全的那一版，独有的章全留，`-Renumber` 重编连续章号，正文不改字。

## 已做过的重叠合并

- 《斗破苍穹x大主宰x武动乾坤之大千绿帽RPG系统》：原 `…RPG系统21～》-40-2.5w`（第 21–30 章）与 `…rpg系统40~60章武祖篇》-全篇-4.4w`（第 41–50 章）。章对齐发现 A 第 23 章与 B 第 43 章同题同文，B 版 4772 字含 A 版 2314 字的 97.2%（32-gram 分块命中 70/72），故重复章取 B 版，其余 19 章全留，重编为 1~19 章，产出 `《斗破苍穹x大主宰x武动乾坤之大千绿帽RPG系统》-1~19章-6.7w.txt`（66986 字）。

## 文件命名

统一使用 `《作品》-章节-字数.txt`，例如 `《斗破苍穹老乞丐》-1~80-41.7w.txt`。

| 字段 | 规则 |
| --- | --- |
| 作品 | 使用原题名或可确认的系列名。去掉原文件名中独立的字数标记。题名含 Windows 文件名禁用字符时，在文件名里换成对应的全角或可用符号。 |
| 章节 | 单章写 `4`，连续章节写 `1~4`，缺章时可按原顺序列出 `21、22、24`。无可靠章号时用 `全篇`，明确的多篇收录可用 `合集` 或 `3篇`。 |
| 字数 | 按输出全文的非空白字符计数，含标点、数字和标题。不足一万写实际数量，如 `943字`。达到一万时以 `w` 表示万，四舍五入到一位小数，去掉末尾的 `.0`。 |

## 校验

- 逐个回读输出 TXT，核对编码和写入内容。忽略排版空白后，输出的字符序列必须与原文一致。
- 合并文件按既定顺序与各份原文拼接后的字符序列比对。每份输入文档在输出中恰好对应一次。
- 当前全库（421 份输出）全部通过校验，逐份记录在 `采集工具\记录\校验报告.csv`。

## 外部工具链（v2 校对引擎）

2026-11-15 起，校对/校验/去重/抽取/OCR 从自写 PowerShell 规则切换到外部库，理由是旧链路在 443 份稿子上仍留下 18 份 HTML 残留、32 份站方广告、146 份半角标点、8 份连续空行。

环境：`uv` 装 **Python 3.12.14**，venv 在 `.venv/`。调用必须先设编码：

```
PYTHONIOENCODING=utf-8 PYTHONUTF8=1 ./.venv/Scripts/python.exe 采集工具/py/<脚本>.py
```

| 脚本 | 作用 | 替代了什么 |
|---|---|---|
| `py/normalize.py` | 校对引擎 v2（编码探测 / ftfy / opencc / 广告库 / 标点 / 接行 / 缩进） | `校对.ps1` |
| `py/build.py` | 从 `原文` 生成校对稿 | `校对.ps1` |
| `py/refresh.py` | 源被升级后按字数比重建 | 手工判断 |
| `py/apply_norm.py` | 落回并改名 | — |
| `py/verify.py` | 校验器 v2（结构 + 字数关系分离） | `校验.ps1` |
| `py/dedupe.py` / `py/dedupe_apply.py` | MinHash LSH 全库近重复 | `查重.ps1` 的 5-gram Jaccard |
| `py/bsc.py` | 蓝色书吧爬虫：`POST /search/` 搜书 → `/index/<bid>/` 目录 → `/read/<bid>/<cid>.html?ajax=1` 取正文（头 `X-Requested-With: XMLHttpRequest`），还原 `<img data-word>` 替字，章节内自动翻页 | `--kw --book --max-books --max-chapters --workers --delay` |
| `py/extract.py` | trafilatura 正文抽取 | `抽正文.ps1` 手写锚点 |
| `py/align.py` | rapidfuzz 章对齐 + cn2an | `章对齐.ps1` |
| `py/ocr.py` | RapidOCR(PP-OCRv4 ONNX) | `OCR.ps1`（PS5.1 + WinRT） |
| `py/harvest_filters.py` | 从 SoNovel 31 书源收割去广告正则 | 手写规则 |

依赖：`ftfy opencc-python-reimplemented cn2an rapidfuzz trafilatura charset-normalizer datasketch regex beautifulsoup4 lxml requests rapidocr-onnxruntime`。

三条硬坑：
1. `ftfy.fix_text` 必须 `fix_character_width=False, uncurl_quotes=False, unescape_html=False`，否则全角 `：“` 被压成 `:"`。
2. 读源文件必须走 `decode_bytes()`（GBK 用 utf-8 读会虚高 60%）。
3. `verify.py` 的字数关系按 `记录/校对清单.csv` 的 Output→Sources 映射算，允许 +2% / -25% 清洗空间。

`噪声词库.json` 来自 [SoNovel](https://github.com/freeok/so-novel) v1.12.0 的 13 个书源规则（31 个子源，59 条 `chapter.filterTxt`），能挡住符号穿插型反过滤广告。

## 校勘层（校勘版\）

| S3 语汇 | 变形/自审的成人语汇还原（`乳#头`→乳头、`高…潮`→高潮 等 40 种手法） | 165 处 |
