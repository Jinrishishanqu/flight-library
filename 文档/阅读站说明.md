# 阅读站与书库说明

本地文库阅读站，与 `站点\`（项目说明站）互相独立。数据源是 `校勘版\` 的 486 个 txt。

## 快速启动

双击 `采集工具\书库\启动.cmd`，浏览器会打开 <http://127.0.0.1:8770/>。

手动启动：

```powershell
cd "F:\新建文件夹\read - 副本\采集工具\书库"
& "..\..\.venv\Scripts\python.exe" server.py 127.0.0.1 8770
```

首次或内容变动后需重建数据库：

```powershell
& "..\..\.venv\Scripts\python.exe" build_db.py --rebuild
```

## 数据库

```
works          作品主表（slug 唯一）
chapters       章节（content 正文、body_bi bigram 索引源）
chapters_fts   FTS5 全文索引，tokenize='unicode61'
characters     出场角色（name/role/mentions）
tags work_tags 标签与关联
fingerprints   标题/文件名/SHA256/开篇 指纹，用于新章节归户
import_log     入库日志
v_works        视图（带 tags 聚合）
```

### 关键设计：bigram 落库

SQLite FTS5 的 `trigram` 分词器**查不了两个字的词**（实测 `MATCH '薰儿'` 返回 0）。
因此 `build_db.py` 用 `bigram_cn()` 把正文按非汉字切段，每段输出相邻二字 token（`"薰儿"` → `薰 儿` 相邻 → 落库为 `薰儿`），
查询侧 `to_fts_query()` 把查询词同样 bigram 化后包成短语 `"美杜 杜莎"`。两个字与多字词都能命中。

实测：`薰儿` 521 节 / 4.6 ms，`美杜莎` 283 节 / <1 ms，`萧炎` 903 节，`淫水` 1074 节。

### 元数据来源

- 书名/字数：解析文件名 `《书名》-全篇-42.5w.txt`
- 原作：目录名映射（`斗破`→斗破苍穹 等 11 组）
- 作者：正文里 `作者[:：]`，无则记 `佚名（原文未标注）`
- 标签：30 条套路词 + 词库类别命中
- 角色：`采集工具\词库\guard.txt` 专名计数 ≥3

### 章节划分

优先按**原文自带的章标记**切，只有标记不完整时才退化为按字数切。

判据（`build_db.py` 的 `split_chapters`）：

| 条件 | 处理 |
|---|---|
| `CHAPTER_RE` 命中 ≥ 3 处，且平均章长 ≤ 30000 字，且最长一段无标记区间 ≤ `max(12×中位间隔, 60000)` | **按原文分章**，`is_real_title=1`，标题用原文 |
| 平均章长 > 30000 字 | 标记只覆盖局部（常见于连载合集），按字数切 |
| 最长无标记区间超阈值 | 标记断裂（只有前几章有标题），按字数切 |
| 命中 < 3 处 | 按字数切，标题 `第N节`，`is_real_title=0` |

细节：

- `CHAPTER_RE = ^[ \t]*(第[0-9零一二三四五六七八九十百千两]+[章节回卷]|序章|楔子|序言|前言|后记|尾声|终章|番外)[^\r\n]{0,40}\r?$`
  —— **行尾必须写 `\r?$`**，否则 CRLF 文件里全部失配（这个坑在项目里踩过四次）。
- 第一个章标记之前的内容（简介、卷首语）作为 `开篇` 单独成节，**不丢弃**。
- 标题与正文粘在同一行时（`第61章升魂丹翌日清晨，阳光透过…`），`split_title()` 把标题截到第一个标点或 24 字，剩下的**还给正文**，一个字都不少。
- 单章超过 12000 字时再按 6000 字细分，标题打 `原名·续N`，避免出现几万字一节。

`采集工具\书库\rebuild_chapters.py` 只重建 `chapters` 表，**不动 works / characters / AI 简介与角色 bio**；跑完自动重灌 FTS。
`章节划分报告.csv` 记录每部书的模式、章标记数、原/新节数、降级原因，入库后可直接核对。

当前状态：`486 部 / 3,584 节`，其中 **1,780 节使用原文真标题**（82 部作品按原文分章），其余 404 部原文没有完整章标记，仍按字数切。


## API

| 端点 | 说明 |
|---|---|
| `GET /api/stats` | 全库计数 |
| `GET /api/works?q=&source=&genre=&tag=&char=&status=&min=&max=&sort=&page=&size=` | 书架列表 |
| `GET /api/works/{id}` | 详情（含角色、标签） |
| `GET /api/works/{id}/chapters` | 目录 |
| `GET /api/chapters/{id}` | 正文 + `prev_id`/`next_id`/`total` |
| `GET /api/search?q=` | 全文检索，bm25 排序 |
| `GET /api/tags` `/api/characters` `/api/sources` | 聚合维度 |

### 多值筛选

`source`、`tag`、`char` 三个参数都接受**逗号分隔的多个值**，语义是「并集」：

```
/api/works?tag=恋足,春药            → 409 + 313 的并集 = 448
/api/works?char=薰儿,美杜莎          → 56 部
/api/works?source=斗破苍穹,斗罗大陆   → 284 部
/api/works?char=薰儿&tag=恋足        → 37 部（不同字段之间是交集）
```

`source=_none` 表示「未归类」（`source_work IS NULL`）。

- `tag` 走 `EXISTS (... t.name IN (?,?))`
- `char` 走 `EXISTS (SELECT 1 FROM characters c WHERE c.work_id=w.id AND c.name IN (?,?))`

### `/api/characters`

按名字聚合，供「按角色分类/筛选」使用，返回 181 个名字：

```json
{"name":"萧炎","m":28448,"works":82,"leads":60,"original":0}
```

- `m` — 全库提及次数合计
- `works` — 出现的作品数（排序键）
- `leads` — 在几部里是主角
- `original` — 在几部里是作者原创角色（非原作角色）

## 前端

4 个页面 + hash 路由，`file://` 也能跑（但建议走 server，字体需同源）：

- `index.html` — 书架（`#/`）、详情（`#/work/12`）、搜索（`#/search?q=`）、分类（`#/cats`）、标签（`#/tags`）
- `read.html?c=456` — 阅读页

`#/cats` 是三组分面：**按原作 11 / 按标签 38 / 按角色 60**。每组卡片点进去就是把该维度作为筛选条件回书架。

筛选抽屉字段顺序：原作 / 类型 / 完成度 / 篇幅 / **角色** / 标签。角色字段带搜索框（181 个名字超出一次能列的量），默认只列「出现在 2 部以上」的或已选中的，输入即全量过滤。

所有多值维度都可以叠加多选，选中项变成可单独移除的 chip（`恋足 ×`、`角色：萧炎 ×`）。

样式拆 4 个文件：`tokens.css`（三主题配色变量）、`base.css`、`components.css`、`reader.css`。
无 Tailwind、无打包步骤——阅读参数 90% 是 CSS 变量，`style.setProperty('--rd-fs','21px')` 即时生效。

### 页面宽度分级

同站三类页面用三档宽度，避免「索引页和内容页一个宽度」导致的空荡感：

| 页面 | 宽度 | 理由 |
|---|---|---|
| 书架 / 搜索 / 分类 / 标签 | `var(--page-max)` 满宽 | 卡片网格，越宽一屏放越多，7 列封面的密度是对的 |
| 作品详情 | **1040px 居中**（`#view.detail`） | 内容页，主信息是「封面 + 简介 + 角色 + 目录」，满宽会让文字行过长、模块间空出大片 |
| 阅读页 | `34em` ≈ 34 汉字/行 | 正文长读，中文舒适行长 30–40 字 |

详情页内部再分三档：

- 简介 `40em` 居中（约 40 汉字/行，`margin-inline:auto`）——原文案是 42em 且左贴，宽屏下会显得「又窄又偏左」
- 目录从 `columns:2` 改成 `grid repeat(auto-fill, minmax(232px,1fr))`——原来是两列各占半屏，「第N节 ……… 6158」被 `space-between` 拉成两大截，列宽收到 232–320 才紧凑
- 角色卡 `repeat(auto-fill, minmax(238px,1fr))`，1040 下自然排成 3 列

`body.is-detail` 会同步收窄顶部状态条（`486 部 · 1893 万字 …`），否则会出现「状态条在 24px、内容在 80px」的错位。

### 阅读排版参数

| 参数 | 桌面 | 平板 | 手机 |
|---|---|---|---|
| 字号 | 19px（14–28 可调） | 18px | 17px |
| 行高 | 1.75 | 1.78 | 1.8 |
| 每行汉字 | 34（`max-inline-size:34em`） | 30 | 20 |
| 段首缩进 | 2em | 2em | 2em |
| 段间距 | **0** | 0 | 0 |

段距 0 + 缩进 2em 是刻意的：全库 28.9% 的段落是对话段（`「` 密度 8.83 次/千字），
段均 55 字≈2 行，用「空一行」体例一屏只剩 6–8 段。

### 阅读位置

存「节 + 段索引」而非 `scrollY`——改字号后行数会变，`scrollY` 会丢位置。

```js
localStorage['rd_pos_' + chapterId] = {c, para, pct, ts}
localStorage['rd_last']              = 最近阅读
```

进度用中线 IntersectionObserver（`rootMargin:-45% 0px -50% 0px`）取当前锚段。

### 其它

- 三主题：墨夜（默认）/ 宣纸 / 靛蓝，存 `localStorage.theme`
- 隐私遮挡：窗口失焦或切页时 `body.veiled` 糊屏，标题变「飞行图书馆」
- 快捷键：`/` 聚焦搜索、`←`/`→` 上下节、`Esc` 关抽屉

## 角色档案（角色卡）

每部作品在详情页「主要角色」区展示 1–8 张角色卡，位置在目录之前。数据全部由脚本从正文抽取，再交给模型写成自然段描述。

### 表结构

`characters` 表关键列：

| 列 | 含义 |
|---|---|
| `name` | 角色名 |
| `role` | 主角 / 配角（提及级角色不入库） |
| `origin` | **原作**（命中 `词库\guard.txt`）/ **原创**（作者自创，靠 `discover_names.py` 发现） |
| `gender` | 男 / 女 / 不明 |
| `mentions` | 全书出现次数 |
| `first_chapter` | 首次出场的节号 |
| `title` | 身份（女王、宗主、封号斗罗…，需同作共现 ≥2 次才认） |
| `intro` | 首现节的一句原文（供生成时参考，前端不再展示） |
| `bio` | **模型写成的 1–4 自然段角色描述**（前端展示的就是它） |
| `bio_at` | bio 生成时间 |
| `story` / `looks` / `figure` / `personality` / `relations` / `sexual` | 旧的结构化字段，bio 缺失时前端回落使用 |

`works` 表有 `summary_ai` / `summary_at`：AI 写成的作品简介，优先于原始的 `summary`。

### 原作角色 vs 原创角色

- **原作角色**：名字在 `采集工具\词库\guard.txt`（104 个斗破/斗罗/诛仙/凡人/大主宰/武动/元尊/遮天/神印人物）里，`origin='原作'`。
- **原创角色**：`采集工具\书库\discover_names.py` 从正文里独立发现的姓名，不在 guard 里，`origin='原创'`，前端卡片上带一枚「原创」小标签。

`discover_names.py` 的判据（缺一不可）：

1. 姓氏法（百家姓单姓 + 复姓表 × 1~2 字）或称谓法（`X大人 / X娘娘 / X公子 / X姑娘 …`）
2. 全书出现 ≥ 6 次
3. `person_score ≥ 0.5` —— 名字前后要跟动作/标点，不是被量词修饰的普通词
4. **末字必须属于 `NAME_CHAR`** —— 挡掉「金币」「毕竟」「屈辱」「冷汗瞬」这类切坏的词
5. 首字不在 `BAD_NAME_HEAD`（后前中上下里外内这那何每某各该本原来去到从向对把被让使给和与同跟及并或而则就都也又还且但却是在），末字不在 `BAD_TAIL`（地得着的然着了过著们么呢吧啊呀）
6. 三字候选若前两字单独高频（`full.count(w[:2]) >= n * 3`）则判为切坏并丢弃（「冉绝刚」12 次 vs「冉绝」3698 次）
7. 不在 `STOP_WORDS`（温柔、安静、明白、江湖、江山…）

### 生成管线

```
build_characters.py      抽角色骨架（guard + discover_names），保留已有 bio 按 name 回填
        ↓
prep_bio_input.py        每部写 data\bio_in\<work_id>.txt：书名/原作/字数/节数/标签
                         + 开头 1200 字 + 每角色 8 条性相关句 + 10 条其他句
        ↓
（模型生成）               agent 直接把结果写进 data\bio_out\<tag>_<nn>_<a>-<b>.json
        ↓
apply_bio.py             读 JSON，写 works.summary_ai 与 characters.bio
```

命令：

```powershell
$py = "..\..\.venv\Scripts\python.exe"
& $py build_characters.py --limit 10            # 全库重建（约 450 秒）
& $py prep_bio_input.py --max 600               # 或有角色作品；加 --all 连无角色作品也出素材
& $py apply_bio.py data\bio_out\d1_*.json      # 可一次传多个文件
```

生成端的 prompt 要点：简介 140–240 字一到两自然段、不用「本文讲述了」开头；bio 1–4 个自然段连贯散文、不分条不用字段名、写身份/做过的事/性格与说话方式/关系/性经历与偏好、允许合理发散、性别判不出填「不明」、不抄原句。

当前覆盖：**486/486 部有 AI 简介，1118/1118 条角色有 bio**。

### 前端渲染

`app.js` 的 `castCard(c)`：有 `bio` 时只渲染 名字 + 称号 / 角色 + 「原创」徽标 + 性别 + 次数 / `div.cast-bio` 逐段 `<p>` / 「全文检索 →」；没有 `bio` 时回落到旧的 `cast-dl`（外貌·身体·性格·关系）与「性」标签块。

`components.css` 对应 `.cast`（`minmax(300px,1fr)` 网格）、`.cast-card`、`.cast-origin`（accent 描边小标签）、`.cast-bio p`（.84rem / 行高 1.85 / 2em 缩进）。

## 未来：新章节归户

`fingerprints` 表已建好四种指纹（`title` / `filename` / `sha256` / `opening`）。
拿到一篇新文章时按此顺序判定：

1. 算全文 SHA256 → 命中则直接跳过（已有）
2. 算开篇 200 字的 SHA256 → 命中则确认是同作续章
3. 书名归一化后比对 `works.title`（去标点、去书名号、同音字归并）
4. 前 3 步都不中 → 用 `/api/search` 取 3–5 个高区分度专名（角色名），
   若这些专名同时出现在同一部作品的正文里且占比高，判为同作

归属确认后把新章节插入 `chapters`（`idx` 取该 work 最大值 +1），并在 `import_log` 记账。

### 已实现：`import_chapter.py`

上面这套判定已经写成脚本，见 `采集工具\书库\import_chapter.py`（零依赖，只用标准库）。

```bat
:: 只诊断，打印候选作品与分数，不写库
python import_chapter.py 新章.txt

:: 整目录批量诊断
python import_chapter.py ..\..\新到货\ 

:: 分数过阈值（默认 6.0）就自动追加章节
python import_chapter.py 新章.txt --apply

:: 已知归属，直接指定作品
python import_chapter.py 新章.txt --work-id 12 --apply
```

打分规则（累加）：

| 线索 | 分值 |
|---|---|
| 全文 SHA256 命中 | +100（直接定案） |
| 开篇 200 字 SHA256 命中 | +90 |
| 书名完全匹配 | +20 |
| 书名互相包含（≥4 字） | +8 |
| 角色共现 Jaccard | +10 × Jaccard |
| bigram 余弦（前面全落空时才跑） | +20 × cos |

`--apply` 的行为：

- 按 `split_chapters()` 切分（文件里有 ≥3 处 `第N章` 就用真标题，否则按 6,000 字切）
- 追加到该作品 `max(idx)` 之后，**假标题接续全书节号**（不会出现第二个「第1节」）
- 短于 400 字的尾节自动并入前一节
- 重建该节的 `body_bi`（FTS 立刻可搜）
- 更新 `char_count` / `chapter_count` / `reading_minutes`
- 写入三种指纹 + `import_log`
- **不覆盖、不删除任何已有章节**

实测（用 `《仙逆之木冰眉失身》` 的后 62% 当未知新章）：识别为 `#1《仙逆之木冰眉失身》`（书名包含 8.0 分），追加 1 节 `idx=4`、标题 `第4节`、6,176 字，作品统计 16,636→22,361 字 / 3→4 节。

## 词库

`采集工具\词库\` 是校勘用的词典知识库，与数据库分离但共同服务于「新文章入库」。

| 文件 | 内容 |
|---|---|
| `guard.txt` | 60 个专名正写（禁改） |
| `confusion.txt` | 异写→正写，带作用域列 |
| `sex_terms.txt` | 174 个成人语汇，分 9 类 |
| `typos.txt` | 错别字对 + 命中数 |
| `char_variants.txt` | 异体字 |
| `watermark.txt` | 26 条盗版水印词 |
| `variants.json` | 打码形态（星号/拼音自审/保留的浪叫风格） |
| `symbols.json` | 符号规范（引号/破折号/省略号/波浪号/括号/分隔线） |

`lib.py` 提供 `Lexicon` 类统一读取。判定顺序硬要求：

```
打码还原 → guard 保护 → confusion 替换 → 断词还原 → 符号统一 → 台账
```

**频次只能发现候选，裁定权在外部权威**（原作设定 / 作品名 / 上下文）。
实测反例：`紫研:紫妍 = 2525:2355` 接近对半，频次投票无意义；
全库 `妖妖 303 > 夭夭 215`，但元尊域内 `妖妖 = 0` —— 全库统计会把别书人名当成本书错字。
