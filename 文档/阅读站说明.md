# 阅读站与书库说明

本地文库阅读站，与 `站点\`（项目说明站）互相独立。数据源是 `校勘版\` 的 486 个 txt。

## 快速启动

双击 `采集工具\书库\启动.cmd`，浏览器会打开 <http://127.0.0.1:8770/>。

手动启动：

```powershell
cd "F:\新建文件夹\read - 副本\采集工具\书库"
& "..\..\.venv\Scripts\python.exe" server.py 127.0.0.1 8770
```

首次或内容变动后需重建数据库：

```powershell
& "..\..\.venv\Scripts\python.exe" build_db.py --rebuild
```

## 数据库

```
works          作品主表（slug 唯一）
chapters       章节（content 正文、body_bi bigram 索引源）
chapters_fts   FTS5 全文索引，tokenize='unicode61'
characters     出场角色（name/role/mentions）
tags work_tags 标签与关联
fingerprints   标题/文件名/SHA256/开篇 指纹，用于新章节归户
import_log     入库日志
v_works        视图（带 tags 聚合）
```

### 关键设计：bigram 落库

SQLite FTS5 的 `trigram` 分词器**查不了两个字的词**（实测 `MATCH '薰儿'` 返回 0）。
因此 `build_db.py` 用 `bigram_cn()` 把正文按非汉字切段，每段输出相邻二字 token（`"薰儿"` → `薰 儿` 相邻 → 落库为 `薰儿`），
查询侧 `to_fts_query()` 把查询词同样 bigram 化后包成短语 `"美杜 杜莎"`。两个字与多字词都能命中。

实测：`薰儿` 521 节 / 4.6 ms，`美杜莎` 283 节 / <1 ms，`萧炎` 903 节，`淫水` 1074 节。

### 元数据来源

- 书名/字数：解析文件名 `《书名》-全篇-42.5w.txt`
- 原作：目录名映射（`斗破`→斗破苍穹 等 11 组）
- 作者：正文里 `作者[:：]`，无则记 `佚名（原文未标注）`
- 标签：30 条套路词 + 词库类别命中
- 角色：`采集工具\词库\guard.txt` 专名计数 ≥3

### 章节划分

优先按**原文自带的章标记**切，只有标记不完整时才退化为按字数切。

判据（`build_db.py` 的 `split_chapters`）：

| 条件 | 处理 |
|---|---|
| `CHAPTER_RE` 命中 ≥ 3 处，且平均章长 ≤ 30000 字，且最长一段无标记区间 ≤ `max(12×中位间隔, 60000)` | **按原文分章**，`is_real_title=1`，标题用原文 |
| 平均章长 > 30000 字 | 标记只覆盖局部（常见于连载合集），按字数切 |
| 最长无标记区间超阈值 | 标记断裂（只有前几章有标题），按字数切 |
| 命中 < 3 处 | 按字数切，标题 `第N节`，`is_real_title=0` |

细节：

- `CHAPTER_RE = ^[ \t]*(第[0-9零一二三四五六七八九十百千两]+[章节回卷]|序章|楔子|序言|前言|后记|尾声|终章|番外)[^\r\n]{0,40}\r?$`
  —— **行尾必须写 `\r?$`**，否则 CRLF 文件里全部失配（这个坑在项目里踩过四次）。
- 第一个章标记之前的内容（简介、卷首语）作为 `开篇` 单独成节，**不丢弃**。
- 标题与正文粘在同一行时（`第61章升魂丹翌日清晨，阳光透过…`），`split_title()` 把标题截到第一个标点或 24 字，剩下的**还给正文**，一个字都不少。
- 单章超过 12000 字时再按 6000 字细分，标题打 `原名·续N`，避免出现几万字一节。

`采集工具\书库\rebuild_chapters.py` 只重建 `chapters` 表，**不动 works / characters / AI 简介与角色 bio**；跑完自动重灌 FTS。
`章节划分报告.csv` 记录每部书的模式、章标记数、原/新节数、降级原因，入库后可直接核对。

当前状态：`486 部 / 3,584 节`，其中 **1,780 节使用原文真标题**（82 部作品按原文分章），其余 404 部原文没有完整章标记，仍按字数切。


### 章号排序：三道护栏与试排检验

`build_db.py` 的 `order_by_chapter()` 只在**排序确实能修好顺序**时才动，其余一律保持原文顺序。三条规则都是踩坑换来的：

| 情形 | 处置 | 为什么 |
|---|---|---|
| 出现「第N卷」 | **不排序** | 分卷结构里每卷章号各自从 1 开始，排序会把各卷同号章交错拼成「六本不同的书」。`#443 诛仙之青云淫徒` 8 卷曾因此被拆散 |
| 本来就没有回退 | 不排序 | 无需改动 |
| 试排后仍有回退 | 不排序 | 说明章号本身不可信（「第三回」这类非章标记混入、或两套序列并存），排了只会更乱 |

配套细节：

- `base_title()` 先剥掉 `·续2`/`·续3` 这类 `split_long` 追加的后缀再取章号 —— 否则同一章的多节会被判成「章号重复」而拒绝排序（`#220` 一直不排序就是这个原因）
- `regressions(nos)` 数「后一个比前一个小」的次数，是唯一的验收标准：排序后必须归零
- `_sort_key()` 给无章号的节分级：`开篇/序章/楔子/前言/序言/引子` 排最前，`后记/尾声/终章/番外/完本` 排最后，其余居中靠后
- 卷名会作为**标题前缀**保留：`第二卷天书和美人 · 第6章机智的水月`。卷名行若正文为空（原文常把卷名单独成行），`split_chapters()` 不会丢弃它，而是交给 `compact_short()` 挂到下一节；同一卷内持续带前缀，直到章号回退（说明已进入下一卷）或出现新卷名行

**效果**：全库章号回退从 29 部降到 **2 部**，且都是真卷结构（`#443` 7 次、`#449` 3 次，属原文事实）。`#220 绿帽之斗破苍穹` 从「第79章 → 第三回 → 第78章 → …倒序」修成 121 节单调递增。


### 书名整理

原始文件名带了一堆连载残留：分卷序号（`5-凡人-逍遥人界篇`、`1~6龙皓晨与众女`）、
合集标记（`唐雅-独立7篇`）、字数标注残片（`（6千5字，`）、作者求支持（`_各位老板…`）、
商业水印（`【客单展示】`、`【约稿作品】`），还有把 `、` 打成 `丶` 的（`牧丶璃`）。

`采集工具\书库\fix_titles.py` 按固定顺序清一遍，`--dry` 只出对照表，`--apply` 才写库。

| 步骤 | 处理 | 例 |
|---|---|---|
| 1 | 开头 `【…】`：商业/状态词丢弃，其余降为前缀 | `【小医仙】冰河谷的追杀` → `小医仙·冰河谷的追杀` |
| 2 | 去 `（付费）（独立2篇）` 前缀 | |
| 3 | 去 `1~6`、`5-`、`7～9` 分卷序号（**必须带分隔符**，否则 `100层塔` 被吃） | `5-凡人-逍遥人界篇` → `凡人-逍遥人界篇` |
| 4 | 去 `（斗1）（1）` | |
| 5 | 去 `独立N篇-` 前缀与 `-独立N篇` 后缀，中英数字都认 | `唐雅-独立7篇` → `唐雅` |
| 6 | 去未闭合的字数标注 | `（6千5字，医仙…` |
| 7 | `_` 后含「各位/老板/求订阅/支持一下…」才删，否则 `_`→`·` | `色孽斗罗_追求力量的朱竹清…` 保留副标题 |
| 8 | 中间夹的 3–4 位章节号改 `·` | `时停系统 0894 美杜莎…` → `时停系统·美杜莎…` |
| 9 | `丶` → `·` | `牧丶璃` → `牧·璃` |
| 10 | 去尾部 ` N卷`、`-N`、汉字后裸 `NN`（≥2 位，避免吃「斗罗大陆2」） | |
| 11 | 以「之」开头且 ≤6 字则去掉「之」 | |

**撞名**：整理后若与已有书名重复，保留原编号做括号后缀，不丢作品 ——
`从斗罗开始收取性奴的诸天之旅（38）`、`叶夕水（2）`。

**改规则后重跑**：`title` 写库后原名就没了，必须先恢复再重跑：

```sql
ATTACH DATABASE 'data\library_before_titles.db' AS bak;
UPDATE works SET title = (SELECT title FROM bak.works WHERE bak.works.id = works.id);
DETACH DATABASE bak;
```

跑完 `--apply` 会 `DROP TABLE chapters_fts` 重灌（书名在 FTS 的 `work_title` 列里）。
当前状态：`数字开头 0`、`含丶 0`、`残留独立N篇 0`，共整理 73 部。

### path_source：原文路径的三路匹配

`path_source` 记录「这篇成品是从哪些原始文件来的」，是回溯与增量入库的锚点。按可靠性降序：
1. **校对清单**（`fill_meta.py`）：`采集工具\记录\校对清单.csv` 的 `Output` basename → `Sources`，覆盖 424 部，多分卷用 `|` 连接。这是最权威的一路 —— 它是 S1 层真正跑过的记录。
2. **文件名模糊**（`fill_source2.py`）：把书名与原文文件名都去掉装饰（`《》`、`1~6` 分卷号、`-全篇-42.5w`、`（1W3字）`、`-独立2篇`），再 `fuzz.ratio ≥ 90`（或 ≥ 82 且目录同名）。补 27 部。
   - 坑：`re.sub(r"^《|》$", "", s)` 只处理首尾，`《书名》-全篇` 会留下中间的 `》`，14 部直接跳过 —— 改成全局 `replace`。
3. **内容指纹**（`fill_source3.py`）：取第 1 节正文去标点后的 **4 个不重叠片段**（offset 0/150/400/800，各 120 字），命中原文任一文件即算，同目录优先。补 39 部。
   - 坑一：`原文\` 里 utf-8 与 gb18030 混存（`大主宰\` 整个目录是 gb18030），必须 `read_bytes()` 后依次试 `utf-8-sig / utf-8 / gb18030 / utf-16`，否则指纹全打不中（只命中 18/40）。
   - 坑二：单一从头开始的指纹会失配 —— `works` 里「标题」与「正文」紧邻，而原文里两者被作者/日期/SIS001 水印隔开，去标点后那个连续串在两处都不存在。
4. **手工兜底**（`fix_source_last.py`）：最后 2 部（原文只有「21～40」那一卷、多段指纹误带入同目录另一篇）。

### notes：数据质量事实

`fill_notes.py` 生成，`；` 连接，只陈述事实不做评价：

- `原文无完整章标记，按 6000 字切节` —— 来自 `采集工具\记录\章节划分报告.csv` 的模式列
- `分卷结构（第N卷），卷内章号各自从 1 开始` —— 章节标题里出现「第N卷」
- `含 N 处私有区字符（源文件乱码，不可逆）` —— 扫 `校勘版\` 正文的 `U+E000–U+F8FF`
- `作者未标注` —— `author` 为空或「佚名」
- `已并入《X》` —— 子本（`merged_into` 非空）

### 体检工具

```bash
python check_db.py              # 只报告：作品/章节/FTS/角色数、空正文、缺简介、字数不一致
python check_db.py --fix-chars  # 把 works.char_count 统一为 SUM(chapters.char_count)
```

`--fix-chars` 的口径说明：`works.char_count` 原本记的是**源文件字符数**（含章标题与换行），`chapters.char_count` 是**正文和**。统一成后者后总字数从 18,453,882 降到 17,951,919（去掉约 50 万字的章标题），更接近「读者看到的字数」。`reading_minutes` 同步按 `char_count / 400` 重算。

## 重复作品整合

同一部作品在采集阶段常被拆成多个文件（分卷、单章单发、短版与加长版、异名版），
入库后会变成多条「看起来不同」的记录。整合的目标是**每个作品只留一条可见记录**，
其余标 `merged_into` 指向主本，内容不重复保留。

### 判据

| 层级 | 手段 | 脚本 | 判定 |
| --- | --- | --- | --- |
| 一 | 全文 sha256（去空白后） | `scan_dupes.py` | 完全一致才合并 |
| 二 | 首尾各 1500 字 sha256 | `scan_dupes.py` | 首尾都相同 |
| 三 | 段级指纹 + MinHash/LSH | `dupe_content.py` | containment ≥ 0.85 |
| 四 | 同作异名候选 | `scan_similar.py` | 书名相似 + 内容重合 + 原创角色同名 |

**书名包含不能当依据**：全库有 103 对「书名互相包含」，其中绝大多数是不同作品
（如「斗破苍穹」⊂「斗破苍穹之始于云岚」）。

**续篇不算重复**：`21 南宫婉失身` 与 `22 续-`、`27 冰灵族银宴` 与 `97 续-`、
`338 唐舞麟与娜儿` 与 `320 新-`，互含都是 0.00 —— 是接续写的第二部，须各自独立。

**异本不合并**：`174 黑暗奴隶拍卖大会` 与 `210`（142k vs 148k）互含仅 0.27/0.28。

**人名不同也是异本**：`167 斗破苍穹 魔法学院`（萧薰儿）与 `175 斗破苍穹`（萧黛儿）
段级重合 0.88，但人名被整体替换，合并后目录里会出现大量近似重复章节 —— 保留双版本。

### 段级去重

`merge_works.py` / `merge_works2.py` 的 `unique_text()`：把子作品逐段切分，每段取
去空白后的**前 24 字**作指纹，若该指纹已存在于主本全文则视为重复段落丢弃。
剩余不足 200 字的子作品视为「无独有内容」，只标 `merged_into` 不追加章节。

### 章节排序

整合时不能简单地把子作品章节追加到末尾。规则：

1. 先按**原文件**排序（同一文件内的章节顺序不动，作者原本的顺序就是正确的）
2. 再按**章号**归并：`build_db.py` 的 `chap_no()` 解析「第十二章」这类中文数字，
   `order_by_chapter()` 只在章号序列非单调时才稳定排序
3. 子作品章节标题是「第1节」这种按字数切的编号时**不认**，改用子作品标题里的章号
   （`CHAP_ONLY` 只认「第N章」）
4. 同章号时主本在前、子本在后
5. 子章节标题统一加前缀 `另版 · 原节标题`（由 `fix_merge_prefix.py` 生成，
   不用子书名全名，避免把目录撑满）

### 短章节压缩

原文里章标题连续出现（目录页、卷首列表）会被 `CHAPTER_RE` 当成独立章节，
产生正文只有 20–60 字的「空章」。`build_db.py` 的 `compact_short()` 把正文
短于 `MIN_BODY = 200` 的真章并入下一节开头（最后一节则并入上一节末尾）。

### merged_into 语义

- `works.merged_into` 为 `NULL` 表示可见作品，否则是主本 id
- `/api/works`、`/api/stats`、`/api/sources`、FTS 重灌都默认排除 `merged_into IS NOT NULL`
- `?merged=1` 可查看全部记录（含已合并）
- 详情页访问被合并的作品时显示「已并入《主本》，不再单独展示」并给跳转按钮
- `import_chapter.py` 的候选匹配排除已合并作品，新章节只会追加到主本

### 与未来追加章节的兼容

合并后的主本章节是连续 `idx`，`import_chapter.py` 用
`SELECT MAX(idx) FROM chapters WHERE work_id=?` 定位追加点，实测对合并后的主本照常工作
（34 节的主本插入一节后变 35 节，`max(idx)` 同步变 35）。

### 撤销

```sql
UPDATE works SET merged_into = NULL WHERE id IN (...);
```
再用 `refresh_fts.py` 重灌搜索表。合并前的完整备份在
`采集工具\书库\data\library_before_merge*.db`。

### 合并插入方式：整块落位，不按章号散插

早期版本（`merge_works2.py`）按章号把子本章节插到主本对应章号的位置，结果一本书被拆成好多段散落各处 ——
《斗破苍穹-改编版》的目录一度是「第三章 → 另版·第三章 → 第四章 → 另版·第四章 …」交错排列。

现在改为 `merge_works3.py`，按**首位交接**处理：

1. **判同文**：子本整体 8-gram 覆盖率 ≥ `SAME_TEXT=0.85` → 判为删节版或分段差异，只写 `merged_into`，一个章节都不追加
2. **剔除头部重合**：从头扫子本的节，连续「与主本重合 ≥50%」的整段丢掉（那是两书重叠的部分）
3. **定位交接点**：拿最后一个重合节去主本里做 10-gram 比对，命中位置就是交接点；没有重合就落到主本末尾
4. **整块插入**：子本剩下的内容**保持原序、作为一整块**插到交接点之后，标题前缀 `另版 · `
5. **续篇例外**：`SEQUEL` 里的对（目前只有 `97→27`）不做重合剔除，全量续接，前缀 `续 · `

主本原有章节的相对顺序一步都不动。实际效果：

```
#168 斗破苍穹-改编版   16 节   主本 15 节 + 末尾整块 1 节「另版 · 第三章密室淫窟」9789 字
#27  冰灵族银宴        4 节   第1节 / 第2节 / 续 · 第1节 / 续 · 第2节
```

22 对里 20 对判同文只标合并，只有 `202→168` 与 `97→27` 真的追加了章节 —— 碎片章节不再产生。

**重建主本时必须先解绑**：`rebuild_chapters.py` 会跳过「有子本的主本」（否则按原文重建会丢掉追加的章节）。
如果要让新的合并逻辑重新落位，顺序是 `UPDATE works SET merged_into=NULL` → `rebuild_chapters.py --apply` → `merge_works3.py --apply` → `refresh_fts.py`。

### 多值筛选

`source`、`tag`、`char` 三个参数都接受**逗号分隔的多个值**，语义是「并集」：

```
/api/works?tag=恋足,春药            → 409 + 313 的并集 = 448
/api/works?char=薰儿,美杜莎          → 56 部
/api/works?source=斗破苍穹,斗罗大陆   → 284 部
/api/works?char=薰儿&tag=恋足        → 37 部（不同字段之间是交集）
```

`source=_none` 表示「未归类」（`source_work IS NULL`）。

- `tag` 走 `EXISTS (... t.name IN (?,?))`
- `char` 走 `EXISTS (SELECT 1 FROM characters c WHERE c.work_id=w.id AND c.name IN (?,?))`

### `/api/characters`

按名字聚合，供「按角色分类/筛选」使用，返回 181 个名字：

```json
{"name":"萧炎","m":28448,"works":82,"leads":60,"original":0}
```

- `m` — 全库提及次数合计
- `works` — 出现的作品数（排序键）
- `leads` — 在几部里是主角
- `original` — 在几部里是作者原创角色（非原作角色）

同站三类页面用三档宽度，避免「索引页和内容页一个宽度」导致的空荡感：

| 页面 | 宽度 | 理由 |
|---|---|---|
| 书架 / 搜索 / 分类 / 标签 | `var(--page-max)` 满宽 | 卡片网格，越宽一屏放越多，7 列封面的密度是对的 |

- 角色卡 `repeat(auto-fill, minmax(238px,1fr))`，1040 下自然排成 3 列

`body.is-detail` 会同步收窄顶部状态条（`486 部 · 1893 万字 …`），否则会出现「状态条在 24px、内容在 80px」的错位。

## 角色档案（角色卡）

### 数据表

`characters` 一行 = **一部作品里的一个角色**，`(work_id, name)` 唯一。同名角色出现在两部书里就是两行，
简介、性别、出场统计彼此独立 —— **不跨作品合并记录**。

| 列 | 含义 |
|---|---|
| `name` | 正名（别名已在统计阶段并入，见下） |
| `role` | 主角 / 配角（由 `score` 分档，不再有「提及」档） |
| `gender` | 男 / 女 / 不明 |
| `mentions` | 全书出现次数（含别名） |
| `coverage` | **出场范围**：把全文切成 100 块，命中的块数 / 100 |
| `spread` | **跨度**：(最后一次 - 第一次) / 全文字符数 |
| `score` | 综合分，决定 role 与排序 |
| `first_chapter` | 首次出场的节号 |
| `origin` | 原作 / 原创 |
| `bio` | AI 写的 1–4 自然段角色卡正文 |
| `title` `intro` `hue` `looks` `figure` `personality` `relations` `sexual` `sex_tags` `story` | 旧结构化字段，保留但前端已不再渲染 |

### 主角判定：看「铺得开」而不是「喊得多」

```python
K_BLOCKS = 100        # 全文切 100 块
MIN_COVERAGE = 0.04   # 出场范围不足 4% 的不要
ROLE_LEAD = 0.55      # score >= 0.55 → 主角
ROLE_SUB = 0.26       # score >= 0.26 → 配角；再低直接不建卡

score = 0.45 * coverage
      + 0.30 * log(1 + mentions) / log(1 + top_mentions)
      + 0.20 * spread
      + 0.05 * chapter_ratio
```

依据是 **Mendenhall 的 composition characteristic curve**（T. C. Mendenhall, *The Characteristic Curves
of Composition*, Science 1887）：把文本等长切段统计某词出现次数，主角的曲线**高而平**，配角**短而集中**。
只看总次数会把「反复被提一句的路人」判得比「贯穿全书但话不多的人」更重要，所以 `coverage` 权重最高。

`spread` 解决「只在开头出现、之后再没露面」的虚高；`chapter_ratio` 是出现过的节数占比。

**一部作品最多 50 张卡**（`--limit 50`，默认值），实际最多的作品 23 人。

### 人名识别：三道门

角色名候选来自两处：`采集工具\词库\guard.txt` 的专名（原作角色）与 `discover_names.py` 的通用人名发现（作者原创角色）。
后者用姓氏法（百家姓 + 复姓 + 1~2 字）与称谓法（`名字+大人/公子/姑娘/长老/宗主/陛下…`），并过三道门：

1. **`person_score >= 0.30`** —— 名字前后是否接动作词或标点
2. **`head >= MIN_HEAD (0.30)`** —— 名字前面不是汉字的比例。真名 ≥0.48，普通词 ≤0.40（`暴露` 0.17、`高贵` 0.09、`冷冰冰` 0.00）
3. **`strong >= MIN_STRONG (0.04)`** —— 前面是标点、后面紧跟说话/动作动词的比例

再加 `NOT_PERSON` 剔除等级与势力词（`斗者/斗师/斗帝/封号斗罗/魂环…`）与常被误判的叙述词（`闻言`/`少年`/`老者`…）。

手工维护、可无限扩展的制表符文件，**性别等不会因作品而变的设定优先从这里读**：

## 未来：新章节归户

`fingerprints` 表已建好四种指纹（`title` / `filename` / `sha256` / `opening`）。
拿到一篇新文章时按此顺序判定：

1. 算全文 SHA256 → 命中则直接跳过（已有）
2. 算开篇 200 字的 SHA256 → 命中则确认是同作续章
3. 书名归一化后比对 `works.title`（去标点、去书名号、同音字归并）
4. 前 3 步都不中 → 用 `/api/search` 取 3–5 个高区分度专名（角色名），
   若这些专名同时出现在同一部作品的正文里且占比高，判为同作

归属确认后把新章节插入 `chapters`（`idx` 取该 work 最大值 +1），并在 `import_log` 记账。

### 已实现：`import_chapter.py`

上面这套判定已经写成脚本，见 `采集工具\书库\import_chapter.py`（零依赖，只用标准库）。

```bat
:: 只诊断，打印候选作品与分数，不写库
python import_chapter.py 新章.txt

:: 整目录批量诊断
python import_chapter.py ..\..\新到货\ 

:: 分数过阈值（默认 6.0）就自动追加章节
python import_chapter.py 新章.txt --apply

:: 已知归属，直接指定作品
python import_chapter.py 新章.txt --work-id 12 --apply
```

打分规则（累加）：

| 线索 | 分值 |
|---|---|
| 全文 SHA256 命中 | +100（直接定案） |
| 开篇 200 字 SHA256 命中 | +90 |
| 书名完全匹配 | +20 |
| 书名互相包含（≥4 字） | +8 |
| 角色共现 Jaccard | +10 × Jaccard |
| bigram 余弦（前面全落空时才跑） | +20 × cos |

`--apply` 的行为：

- 按 `split_chapters()` 切分（文件里有 ≥3 处 `第N章` 就用真标题，否则按 6,000 字切）
- 追加到该作品 `max(idx)` 之后，**假标题接续全书节号**（不会出现第二个「第1节」）
- 短于 400 字的尾节自动并入前一节
- 重建该节的 `body_bi`（FTS 立刻可搜）
- 更新 `char_count` / `chapter_count` / `reading_minutes`
- 写入三种指纹 + `import_log`
- **不覆盖、不删除任何已有章节**

实测（用 `《仙逆之木冰眉失身》` 的后 62% 当未知新章）：识别为 `#1《仙逆之木冰眉失身》`（书名包含 8.0 分），追加 1 节 `idx=4`、标题 `第4节`、6,176 字，作品统计 16,636→22,361 字 / 3→4 节。

`lib.py` 提供 `Lexicon` 类统一读取。判定顺序硬要求：

```
打码还原 → guard 保护 → confusion 替换 → 断词还原 → 符号统一 → 台账
```

**频次只能发现候选，裁定权在外部权威**（原作设定 / 作品名 / 上下文）。
实测反例：`紫研:紫妍 = 2525:2355` 接近对半，频次投票无意义；
全库 `妖妖 303 > 夭夭 215`，但元尊域内 `妖妖 = 0` —— 全库统计会把别书人名当成本书错字。
