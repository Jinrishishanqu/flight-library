# 本地阅读站 · 视觉与交互设计规范 v1

> 对象：486 部 / 1,890 万字 中文成人向同人长篇，单机自用，桌面优先、手机可读。
> 交付形态：静态 HTML + CSS 变量 + 原生 JS，无构建步骤。
> 本文所有数值可直接抄进 CSS；对比度由 WCAG 2.1 相对亮度公式实算（脚本见文末附录）。

---

## 0. 五个决定（先看这个）

1. **正文用宋体，19px / 行高 1.75 / 每行 34 字**，UI 用黑体，题记/引文用霞鹜文楷。
2. **深色为默认主题**（墨夜 `#14110E`），浅色是「宣纸」`#F4EFE6`；不用纯黑纯白。
3. **阅读位置用「段落索引」记忆**，不用 scrollY——字号一变 scrollY 就废了。
4. **384/486 部没有章节标记**（实测），章节目录必须自动切节（每 8000 字一节，取首段前 12 字作标题）。
5. **封面缺失当风格处理**：竖排书名「字封面」+ 6 组布面色，不做占位图。

## 1. 语料实测（设计依据，不是猜的）

| 指标 | 实测值 | 设计含义 |
|---|---|---|
| 作品数 / 总字数 | 486 / 18,243,112（README 计 1,890 万，含空白） | 书架规模中等，无需虚拟滚动 |
| 单篇字数 | 均值 38,900；最长 1,382,745 | 大多数是「中篇」，但存在 138 万字单体，必须分段加载 |
| 有 `第X章` 标记 | **102 部（1205 章），384 部为 0** | 章节导航必须自动生成，不能依赖源文本 |
| 段落总数 / 段长 | 331,909 段，均值 **55 字**，中位 47，p90 118 | ≈ 每段 2 行；**段间距必须小**，否则页面碎裂 |
| 对话段占比 | **28.9%** 的段落以 `「` 开头；`「` 出现 8.83 次/千字 | 近三成是对话行，缩进体例必须统一，否则左右边参差 |
| 段首全角空格 | **0%** | 可以安全使用 `text-indent: 2em`，不会双缩进 |
| 唯一字符数 | **5,545** | 字体子集只需 5.5k 字 → woff2 约 1.5–2MB，切片后首屏可压到 ~100KB |
| 编码 | UTF-8，LF | — |

字符集已导出：`文档\_charset.txt`（16.5KB，可直接喂 `pyftsubset --text-file=`）。

**结论：这是「短段 + 高对话密度」的文本。**排版上必须选「首行缩进 2em + 段距 0」，而不是「无缩进 + 空一行」——后者会让 64 字一段的文字占三行版面，一屏只能放 6 段，翻页感极差。

## 2. A. 阅读器排版规范

### 2.1 参数总表

| 参数 | 桌面（≥1024） | 平板（641–1023） | 手机（≤640） | 说明 |
|---|---|---|---|---|
| 字号 | **19px**（16–26 可调，步进 1） | 18px（16–24） | **17px**（15–22） | 1rem = 16px，19px = 1.1875rem |
| 行高 | **1.75**（33.25px） | 1.78 | **1.8** | 宋体 1.72–1.8；黑体 1.66–1.72；楷体 1.85–1.9 |
| 字距 | **0.015em**（0.29px） | 0.01em | **0** | 超 0.05em 字群散架；手机上正字距反而减少每行字数 |
| 段首缩进 | **2em**（38px） | 2em | 2em | 纸书体例，与「无空行」配套 |
| 段间距 | **0** | 0 | 0 | 见 2.4 的替代方案 |
| 行长（每行汉字） | **34 字**（646px） | 30 字（540px） | **20 字**（350px） | jlreq：横排上限 40 字；中文书籍常规 28–36 |
| 容器 | `max-inline-size: 34em` | `30em` | `100%` | 用 em 而非 px，保证整字行宽 |
| 左右留白 | `padding-inline: 28px` | 24px | **20px** | 内容居中后，1280 视口两侧各 317px |
| 段内行首禁则 | `line-break: strict` | 同 | 同 | 避免 `「」、，。` 出现在行首 |
| 对齐 | `text-align: start`（左对齐） | 同 | 同 | 中文等宽字形，参差不可见；`justify` 在短段+混排西文时会产生拉伸 |

**字号联动**：宋体字面率约 0.86em，黑体约 0.92em。用户切到黑体时同一 `font-size` 会显得大 6–7% → 用 `font-size-adjust` 或直接让「字体方案」自带字号补偿（黑体 −1px）。

### 2.3 字体结论（含许可证）

| 字体 | 类 | 字重 | 许可证 | 用在哪 |
|---|---|---|---|---|
| **思源宋体 Source Han Serif SC** / Noto Serif CJK SC | 宋 | 7（ExtraLight–Heavy） | **SIL OFL 1.1** | 正文首选；19px 起 |
| **思源黑体 Source Han Sans SC** / Noto Sans CJK SC | 黑 | 7 | **SIL OFL 1.1** | UI、元数据、按钮、数字 |
| **霞鹜文楷 LXGW WenKai** | 楷 | 3（Light/Regular/Medium） | **SIL OFL 1.1** | 题记、引文、作者按语；**不做正文** |
| 霞鹜文楷 Screen | 楷 | 1（Medium 基准，度量对齐 Roboto） | SIL OFL 1.1 | 手机端专用 |
| 霞鹜致宋 LXGW ZhiSong | 宋 | — | 开源（以仓库 LICENSE 为准） | 轻量宋体替代（体积比思源小） |
| 更纱黑体 Sarasa Gothic | 黑/等宽 | 多 | SIL OFL 1.1 | 代码块、文件信息 |
| 方正/汉仪等 | — | — | 商业授权 | 不用 |

**衬线 vs 无衬线的实测结论（诚实的版本）：**

- 中文长读的**主导变量不是衬线，是 字号 × 行高 × 行长 × 对比度**。同样是 19px/1.75/34 字，宋体与黑体的阅读速度差在实验噪声内；差异体现在**主观疲劳与「文学感」**，不在速度。
- 宋体在**高 DPI（≥2x）+ 字号 ≥18px** 时优势明显：横细竖粗形成字头识别线索，行内节奏更像铅字；在 **1x 屏 + ≤16px** 时细横会糊成灰线，此时黑体更清晰。
- 霞鹜文楷作者本人的结论可以直接引用：**「这款字体可能并不太适合大段正文排版，相比之下更加适合诗词之类的中等长度文本排版，或者注释排版」**（项目 README）。→ 文楷做「题记/卷首/引文」，不做 20 万字正文。这是最省事、也最不容易翻车的分工。
- 落地策略：正文默认思源宋体，设置里给「宋 / 黑 / 楷」三档一键切换，并把字号补偿算法绑定到字体档位。低视力用户切黑体；追求氛围切楷体（自动 +2px 字号、行高 1.9）。

### 2.4 段距 vs 缩进的取舍

文本均值 55 字 ≈ 2 行（28.9% 的段落还是对话单行）。若用「无缩进 + 0.75em 段距」，一屏（900px）只能容纳约 8 段，纵向节奏被切碎，长文读起来像列表。

**默认：「缩进 2em + 段距 0」**（纸书体例）。设置面板另给一档 `段间空行`（indent 0 / gap 0.7em），只对偏好者开放，且不影响位置记忆（位置按段落索引记）。

对话段（以 `「` 开头）保持 2em 缩进，不额外处理——这是中文书籍惯例，也避免和旁白段产生视觉断层。

### 2.5 深色模式参数（为什么不是纯黑纯白）

| 项 | 值 | 对比度 |
|---|---|---|
| 页面背景 | `#14110E`（L\* 5.3） | — |
| 阅读区背景 | 同页面（不叠卡片，全幅） | — |
| 正文 | `#DED6C8`（暖灰，色温≈4000K） | **13.04 : 1** |
| 正文（高对比档） | `#E8E1D5` | 14.48 : 1 |
| 次要文字 | `#A79B8A` | 6.90 : 1 |
| 装饰文字 | `#7C7263` | 3.98 : 1（仅 ≥18px 或非信息） |
| 分隔线 | `#2F2822` | 1.30 : 1（发丝线，不刺眼） |
| 强调（链接/按钮） | `#D0825C` | 6.30 : 1 |

**不用 `#000` 的四条理由：**
1. OLED 上纯黑 + 亮字会产生 halation（光晕/拖影），暗环境瞳孔放大时更明显，字形边缘「发毛」；
2. 纯黑让容器失去边界，全屏阅读时没有「纸面」的空间感，只剩悬浮的字；
3. 纯黑使明度层级不可用（无法用 L\* 区分页面/卡片/浮层），只能全靠描边；
4. 21:1 的对比度远超阅读所需，等于持续眩光。

**不用 `#FFF` 的理由：** 色温 6500K+ 蓝光占比高，夜间抑制褪黑素；与暗环境亮度落差大，切换页面时瞬盲。用 `#DED6C8` 把对比度压在 **12–15:1** 区间——这是夜间长读的舒适带（WCAG AAA 只要求 7:1，但低于 10:1 会显得「灰扑扑」）。

夜间再给一个 `对比度微调`（0.85–1.0），实现为正文 `opacity` 或直接插值 `--rd-fg`，避免用户手动改色。

### 2.6 分页 vs 滚动 · 进度记忆 · 章内定位

**结论：连续滚动为默认，按屏翻页为可选，仿真翻页不做。**

- 分页的问题：138 万字单体作品无法预分页；字号/行高/窗口一变就要全文重排，位置会漂。中文没有断词连字符，重排成本比西文更高。
- 无限滚动的问题：直接渲染 3 万段会卡死。解决办法不是分页，是**分段载入 + `content-visibility`**：

```css
.rd .sec{ content-visibility: auto; contain-intrinsic-size: auto 1200px; }
```
先渲染 5,000 字，`IntersectionObserver` 触底再追加 5,000 字，每节容器套上面的规则让离屏段落跳过布局。

- **按屏翻页**（折中方案，推荐做）：容器 `scroll-snap-type: y mandatory`，以视口高度为节拍，`scroll-snap-align: start`。不切割段落，因此没有孤行，也保留了「翻一屏」的仪式感。键盘 PageDown / Space 天然对齐。

**进度记忆（关键实现细节）：**

```js
// 不要存 scrollY —— 字号一变全废
localStorage['rd:pos:' + workId] = JSON.stringify({
  sec: 7,          // 第几个分段容器（每 8000 字一节）
  para: 128,       // 该节内第几段
  ratio: 0.62,     // 全文百分比，用于进度条与「剩余 xx 分钟」
  ts: Date.now()
});
```
锚点采集用中线判定，避免「露出 1px 就算读过」：

```js
new IntersectionObserver(es => {
  // rootMargin 把判定线压到视口中线附近
}, { rootMargin: '-45% 0px -50% 0px' });
```
位置还原：`el.scrollIntoView({block:'start'})` 后再补偿一次，因为图片/字体加载会顶动版面——用 `font-display: optional`（见 §5.2）可直接消灭这个抖动。

**章内定位：**
- 顶部 2px 细进度条，可拖动（拖动时显示「第 34 节 · 62%」气泡）；
- 目录抽屉：有真章节用真章节（1205 章），无章节用自动切节（384 部）——标题取该节首段前 12 字、去掉引号，形如 `「他推开门，看见……」`；
- 快捷键：`j/k` 或 `↑/↓` 滚动、`空格/⇧空格` 翻屏、`←/→` 上/下一节、`[ ]` 调字号、`Esc` 收抽屉、`t` 切主题；
- 触控：左右滑 = 上/下一节，中央轻点 = 显隐 chrome（chrome 上滑顶部出现、下滑出现底栏）。

**沉浸态：** 进入阅读页 `body[data-immersive]`，隐藏站点 header，鼠标静止 2.5s 后 `cursor: none`（仅桌面，移动端不启用）。

## 4. C. 信息架构与交互

### 4.1 书架首页

- **网格**：`grid-template-columns: repeat(auto-fill, minmax(150px,1fr)); gap:16px`。1180 容器 → 6 列（183px 宽 / 275px 高）；平板 4 列；手机 2 列（gap 12px）。
- **列表**：行高 52px，左缩略图 36×54，中书名+作者，右字数/进度，底部 2px 进度条。列表模式用于「按进度找书」。
- **滚动容器**：486 张卡片 ≈ 6–8k DOM 节点，**不需要虚拟滚动**（这点别过度设计）。用 `content-visibility:auto` + `contain-intrinsic-size: 0 300px` 就够。
- **控件不打断浏览**：
  - 吸顶工具条 56px（`position:sticky; top:0; backdrop-filter:blur(10px)`）：搜索框（输入即筛，**不跳页**）· 排序按钮（popover，6 项：最近阅读/新入库/字数/标题拼音/原作/随机）· 视图切换 · 筛选按钮；
  - **筛选器放抽屉**（右侧 360px / 手机 bottom-sheet），内含分组 facet + 每组命中数，底部「应用 / 重置」；
  - 已激活的筛选以**一行 chip** 常驻工具条下方，单个 `×` 可移除；chip 超过 3 个折叠为「+4」；
  - 结果变化用 `document.startViewTransition()` 做 FLIP 过渡（Chrome 原生，无需库），避免「闪一下重排」；筛选变化时滚动回顶部，但过渡保持连续感。
- **空/少状态**：书架首屏顶部固定一行「继续阅读」横滑（最多 6 本，按 `ts` 排序），这是自用站最高频入口，不要塞进网格里。

### 4.2 作品详情页

**三层信息密度**，从上到下递减：

1. **身份层（hero）**：书名 34px 宋体 + 作者/原作 14px + 一行事实 `12.5 万字 · 34 章 · 已读 62%`（数字用 `font-variant-numeric: tabular-nums`）；
2. **动作层**：主按钮「继续阅读 · 第 34 节 62%」（描边+实底各一），次按钮「从头开始 / 收藏 / 加入稍后」；
3. **属性层**：标签 chips，最多显示 8 个 + `还有 7 个`；
4. **溯源层**：`<details>` 折叠「文件信息」——源站、采集时间、编码、校勘状态、字数/段数、SHA 前缀。

元数据用 `dl` 两列网格，**每行最多 3 组**，组间用 16px 空隙而非线条：

```css
.meta{ display:grid; grid-template-columns:max-content 1fr; gap:8px 16px; font-size:13px; }
.meta dt{ color:var(--fg-2); }
.meta dd{ margin:0; color:var(--fg); }
```

布局：桌面两栏（左 240px 封面 `position:sticky; top:80px`，右自适应）；手机单栏，封面缩到 96×144 与书名同行。

**章节目录**（本项目的特殊点）：
- 102 部有真章节 → 直接列，双列（桌面）/ 单列（手机），当前节高亮；
- 384 部无章节 → 自动切节：按段落索引累积字数，每 **8,000 字**切一节，标题取该节首段前 12 字（去引号、去空白），编号 `01 / 02 / …`；
- 目录项右侧标该节字数与「已读」标记，支持键盘 `↑↓` + `Enter`。

### 4.3 标签体系（几百个标签怎么不变成一堵墙）

三层结构，避免词云：

1. **固定维度（facet，单选/多选）**：原作（斗破/斗罗/大主宰…11 组）、性向、尺度、篇幅（<5 万 / 5–20 万 / >20 万）、完成度。固定维度用「分段控件（segmented control）」，不用标签云。
2. **高频入口**：按作品数排序的前 60 个标签，4 列网格，每项 `标签名 + 计数`，**字号统一 13px**——用「排序 + 计数」表达权重，不用字号差三倍（那就是词云，读不动）。
3. **索引**：`/tags` 页左侧拼音首字母索引（A–Z），右侧分组列表；顶部一个「标签搜索」框，输入即过滤。

**破墙的关键是「共现」**：进入任一标签详情，除作品列表外，必须给出「常与之同时出现的标签 Top 8」（由共现矩阵预计算，静态 JSON 即可）。用户从「足交」能走到「恋足 → 斗破 → 调教」，这才是「可浏览」。

标签点击 = **在书架上应用筛选**（`#tags=a,b`），不跳独立页，保持浏览连续性；标签详情页只作为「探索入口」存在。

### 4.4 搜索结果页

- **默认按作品聚合**：顶部 `命中 47 部 / 812 处`；每部作品卡片内最多 3 条命中片段，附「还有 12 处」展开。
- **切换「逐条片段」视图**：找特定情节时用（1900 万字里翻一段，聚合视图反而挡路）。
- 片段窗口 **90 字**（命中词前 40 / 后 50），命中词 `<mark>`；片段里再截断时用 `…` 而不是 `...`。
- 排序：`标题命中 ×5 + 标签命中 ×3 + 正文命中密度`，并提供「最近在读优先」开关。
- 输入：`debounce 200ms`，**≥2 字**才发查询（单字命中量爆炸）；拼音/错字用编辑距离 1 的「你是不是要找」兜底。
- 高亮样式：`mark{ background:var(--mark-bg); color:inherit; border-radius:2px; padding:0 .1em }`，深色下用半透明暖色而非亮黄。

## 5. D. 技术落地

### 5.1 CSS 方案：纯 CSS 变量 + 少量原生 JS（不用 Tailwind）

理由，按重要性排：

1. **没有构建链**。现在是「双击 index.html」的静态站，Tailwind 需要 node/pnpm + 构建产物，一旦想改一个 `text-indent` 就要跑一次 CLI，和本项目「改一行看一行」的工作方式冲突。
2. **阅读器参数的 90% 是 CSS 变量**（字号/行高/字距/缩进/行宽/主题色）。原生 `style.setProperty('--rd-fs', '21px')` 即可实时生效，Tailwind 无法表达这种「运行时连续量」——只能写一堆 arbitrary values（`text-[19px] leading-[1.75] tracking-[0.015em]`），比手写 CSS 更长。
3. **中文排版的属性都在 Tailwind 的边缘**：`line-break:strict`、`hanging-punctuation`、`text-spacing-trim`、`writing-mode:vertical-rl`（竖排书名）、`text-indent:2em` 全要 arbitrary value 或 `@layer` 手写，等于写两套。
4. **体积**：整个站 CSS 预算 25KB（未压缩），自写 tokens+components 约 300 行；Tailwind 输出 10–30KB 且需要 purge 配置。
5. 组件复用需求低：全站 5 个页面、约 12 个组件，CSS 类命名（BEM 简版）比原子类更好维护。

**目录：**

```
站点/
  assets/tokens.css      变量 + 三主题（约 80 行）
  assets/base.css        reset + 排版基座 + 布局（约 120 行）
  assets/components.css  卡片/按钮/chip/抽屉/表格（约 200 行）
  assets/reader.css      阅读页专用（约 120 行）
  assets/app.js          筛选/排序/视图/主题（约 200 行）
  assets/reader.js       参数面板/进度/节流加载（约 250 行）
  assets/search.js       查询与片段渲染
  assets/fonts/*.woff2
  index.html  work.html  read.html  tags.html  search.html
```

**路由**：`file://` 下 `history.pushState` 不可用 → 全站用 hash：`read.html#w=123&s=7&p=128`。4 个页面 + hash 参数，比 SPA 路由稳，也比生成 486 个 HTML 好维护。

**参数持久化：**

```js
const K='rd:prefs';
const P=Object.assign({theme:'ink',fs:19,lh:1.75,ls:0.015,indent:2,gap:0,font:'serif'},
                      JSON.parse(localStorage[K]||'{}'));
function apply(){
  const r=document.documentElement.style;
  document.documentElement.dataset.theme=P.theme;
  r.setProperty('--rd-fs',P.fs+'px');
  r.setProperty('--rd-lh',P.lh);
  r.setProperty('--rd-ls',P.ls+'em');
  r.setProperty('--rd-indent',P.indent+'em');
  r.setProperty('--rd-para-gap',P.gap+'em');
  document.body.dataset.font=P.font;
  localStorage[K]=JSON.stringify(P);
}
```
字体档位用 `body[data-font="serif"|"sans"|"kai"]` 切换 `--f-serif` 并自动补偿字号（黑体 −1px、楷体 +2px）。

**隐私细节（这个站的「私密感」来自这里，不是配色）：**
- 标题可设「安全标题」：`document.title` 在失焦后替换为「资料库」；
- `visibilitychange` 隐藏时给 `body` 加 `.veiled{ filter:blur(16px) saturate(.6) }`，回来 120ms 淡入；
- 不在封面/空状态放任何露骨图形，视觉全部靠材质（布面、纸、铜、发丝线）。

### 5.2 中文字体子集化（这是本项目体积的大头）

**数字感（按本项目实测校正）：** 思源宋体 SC 单字重 TTF ≈ 9–11MB；全量转 woff2 ≈ 4–5MB；子集到本项目 **5,545 个唯一字符** ≈ **1.5–2.2MB**；再按 `unicode-range` 切片 40–100 片后，**首屏只需 80–150KB**。黑体 UI 字重同理，可再压 30%。

**做法（三段）：**

1. **提取本项目字符集**（已跑过，结果在 `文档\_charset.txt`，16.5KB / 5,545 字）：

```python
import glob, collections
chars = set()
for p in glob.glob('校勘版/**/*.txt', recursive=True):
    chars |= set(open(p, encoding='utf-8').read())
chars = {c for c in chars if not c.isspace()}
open('chars.txt','w',encoding='utf-8').write(''.join(sorted(chars)))
print(len(chars))
```

2. **子集化 + woff2**：

```bash
pip install fonttools brotli
pyftsubset SourceHanSerifSC-Regular.otf \
  --text-file=chars.txt \
  --flavor=woff2 \
  --layout-features='kern,liga,vert,vrt2,palt,halt' \
  --no-hinting --desubroutinize \
  --output-file=shserif-sub.woff2
```
`--layout-features` 里 `vert/vrt2` 必须留（竖排书名要用），`palt/halt` 用于标点压缩。

3. **切片**（首屏别吞 3MB）：用 `cn-font-split` 或手写 `unicode-range` 分段（BMP 常用区 4E00–9FFF 按 400 字一片），CSS 写成：

```css
@font-face{
  font-family:"SH Serif Sub"; src:url(fonts/shserif-01.woff2) format("woff2");
  unicode-range:U+4E00-51FF, U+3000-303F; font-display:optional;
  ascent-override:88%; descent-override:12%; size-adjust:100%;
}
```
浏览器只下载「页面上真正出现过的码位」所在的分片——一本 4 万字的中篇通常只触发 2–4 片。

**`font-display: optional` 而不是 `swap`**：swap 会在 1–3s 后突然换字体，正文重排、阅读位置漂移。optional 的语义是「本次会话没加载到就用回退字体」，换来绝对稳定的版面和位置记忆。

**⚠️ `file://` 的坑（必须处理）：** Chrome 打开本地 `file://` 页面时，`@font-face` 请求被视为跨源（origin 为 `null`），会被 CORS 拦掉，报 `Access to font at '...' from origin 'null' has been blocked`。三条出路：

1. **推荐**：站内加 `启动.cmd`，跑 `python -m http.server 8787` 并 `start http://localhost:8787`（项目已有 `.venv`，零安装）；
2. `local()` 优先：`src: local("Source Han Serif SC"), url(...)`，本机装了思源宋体就直接命中，不发起请求；
3. 兜底字体栈把 `Songti SC / SimSun` 写全，保证无字体时仍是宋体骨架（不要回落到 sans）。

### 5.3 全文检索（1900 万字的现实约束）

- 前端索引不可行：MiniSearch/FlexSearch 对 1,890 万字建 bigram 索引约 150–300MB，浏览器加载即崩。
- **推荐：SQLite FTS5 + 本地小服务**（Python 已有），trigram 分词器天然支持中文子串：

```sql
CREATE VIRTUAL TABLE fts USING fts5(
  wid UNINDEXED, sec UNINDEXED, para UNINDEXED,
  title, body, tokenize="trigram"
);
-- 查询 + 自带高亮片段
SELECT wid, title,
       snippet(fts, 4, '<mark>', '</mark>', '…', 90) AS frag,
       bm25(fts) AS score
FROM fts WHERE fts MATCH ? ORDER BY score LIMIT 200;
```
`trigram` 要求查询 ≥3 字；2 字查询走 `body LIKE '%xx%'` 兜底（1900 万字 LIKE 全扫约 1–2s，可接受，或再加一列 `unicode61` + jieba 预分词）。索引体积约为原文 3–4 倍（≈200MB），单机无压力。

- 纯静态降级方案：预生成 `search/` 下按作品切分的倒排 JSON（bigram），只在「已打开的作品内搜索」，不做全库——覆盖 80% 实际需求。

```python
def lin(c):
    c /= 255
    return c/12.92 if c <= 0.04045 else ((c+0.055)/1.055)**2.4
def L(h):
    h = h.lstrip('#'); r,g,b = (int(h[i:i+2],16) for i in (0,2,4))
    return .2126*lin(r) + .7152*lin(g) + .0722*lin(b)
def cr(a,b):
    la, lb = L(a), L(b); hi, lo = max(la,lb), min(la,lb)
    return (hi+.05)/(lo+.05)
def lstar(h):
    y = L(h)
    return 116*y**(1/3)-16 if y > .008856 else 903.3*y
```
