采集管线

五段流水线：搜集 → 入库 → 校对 → 合并/查重 → 校验/索引。 每一段都有明确的判定标准，不靠感觉。

  路线 A  版主爬.ps1   →  站上文字能直取：搜索 → 目录 → 逐章 div#nr1 → raw/
  路线 B  截图.ps1     →  Edge 无头截图 → OCR.ps1（WinRT）→ raw/
                              ↑ 给「文字在 canvas / 图片里 / JS 渲染 / 登录墙后」的站

      ↓  采集工具/raw/*.txt
      ↓

      ↓

      ↓                                  → 校对后文章/<IP>/《作品》-章节-字数.txt
合并.ps1 / 章拼接.ps1 / 重叠合并.ps1  →  多章并一件、跨文件去重叠
      ↓

一键跑：流水线.ps1

pwsh -NoProfile -File 采集工具/流水线.ps1 -Mode crawl -Queries "绝世唐门,诛仙" -MaxBooks 4
pwsh -NoProfile -File 采集工具/流水线.ps1 -Mode full -Urls "https://a|https://b" -Title "书名" -FullPage
powershell -File 采集工具/流水线.ps1 -Mode post      # 只跑后处理链

Mode 五档：crawl 爬文字 / shot 只截图 / ocr 只转文字 / post 只跑后处理 / full 截图+OCR+后处理。日志写 记录/流水线.csv。OCR 必须由 powershell.exe 5.1 执行，pwsh 7 加载不了 Windows.Media.Ocr。

第一段 · 搜集：搜什么词决定一切

同一个源，换关键词命中率差 4 倍。这是整个工程里最值钱的一条经验。

搜索方式示例命中率说明
关键词「同人」斗破苍穹 同人21%tag 下 60 篇只有 13 篇是 H
角色名 + H 词萧薰儿 调教80–90%主力打法
作品名 + H 词斗罗大陆 催眠80–90%量大但重复多
系列 tag 补扫-Tags 斗破苍穹 -Pages 5中能捞到大件（47.9 万字全本）
作者线靶-Group tudou低池子早晚见底，第三轮只净增 3 篇

规则：H 判定

  • tag 命中任一 H 词 → 直接判 H
  • 否则按 hWords（66 词）密度，≥ HMin=2 才收
  • 词表要够宽：调教 / 中出 / 淫 / 凌辱 / 催眠 / 肉 / 奴 / 媚药 / 淫液 / 后穴 …

第二段 · 入库：三层判重

① MD5

字节级完全相同。挡住同文件重复下载。

② 标题归一

去标点/空格/版本标记后比对。挡住「斗破苍穹(1)」「斗破苍穹 修正版」。

③ 前 200 字指纹

挡住同文异名。但这一层会漏近重复——后来靠 查重.ps1 的 5-gram Jaccard 补上。

归类的坑：入库.ps1 只对 raw/ 根目录的文件跑 Resolve-Ip。 如果把 txt 放进 raw/某子目录/，子目录名会被当成 IP 名，整批归错类。

归类靠 ipRules 计分（角色名权重最高）。已知误判：绝色小医仙 被分进「大主宰」。

第三段 · 校对：v2 引擎（Python）

校对已从 校对.ps1（PowerShell 手写规则）升级为 py/normalize.py（外部库 + 规则库），因为 PowerShell 版产出的稿子里还留着 18 份 HTML 残留、32 份站方广告、146 份半角标点、8 份连续空行。

校对：README 里的硬规则（仍然有效）

规则做什么为什么
固定行宽接回被硬折行的段落重新拼成一整段源站按 40 字换行，不接回没法读
标点错断接回句末标点后紧跟下一行的接上避免一句话被劈成两段
段落标记空行分段，统一 CRLF后续合并/断句全靠这个
编码UTF-8 with BOMWindows 记事本不乱码
章号合并同书连续章号并成一件（含中文数字）单章文件太碎
命名《作品》-章节-字数.txt，≥1 万字用 w排序和肉眼扫读
校对.ps1 不是增量脚本。它每次从 原文/ 全量重建。人工合并过的族、查重移出的重复件，重跑一次就全回来了。 重跑后必须执行 清理再生.ps1 -Apply 把它们移走，否则前功尽弃。

第四段 · 合并与去重

多章并一件（families 驱动）

families.psd1 里每条族定义：

@{ Dir='斗破'; Title='斗破·萧薰儿篇'; Match='^萧薰儿篇'; Need='' }
@{ Dir='斗罗'; Title='斗罗·（加料）全本'; Match='^（加料）'; Span='1~80（缺41-60章）' }
  • Match 对去掉《》后的裸标题做匹配（文件名都带前导书名号，不剥就永远匹配不上）
  • Need 是首行正则，用来确认「这一章真的是这本」（回目连载靠 【第X回，墨白线靠 【第X章）
  • 同章两版取长度更长的；章号 0（-全篇-）单独按文件名长度排序放最前

重叠拼接（同一本书两个残卷）

RPG 系统那一对的真实情况：A 有第 21–30 章，B 有第 41–50 章，唯一重复是 A 第 23 章 ≈ B 第 43 章，相似 99%，32-gram 分块命中 70/72 = 97.2%，B43 是 A23 的超集。

处理：章对齐.ps1 找重复章 → 人工定 Plan → 章拼接.ps1 -Renumber 按 Plan 顺序拼，重复章取 B 版，重编 1–19 章。

pwsh -NoProfile -Command '& "采集工具\章拼接.ps1" -PathA A.txt -PathB B.txt `
  -Plan @("A:0","B:0","A:21","A:22","B:43","A:24","A:25","A:26","A:27","A:28","A:29","A:30",
          "B:41","B:42","B:44","B:45","B:46","B:47","B:48","B:49","B:50") `
  -Title "斗破苍穹x大主宰x武动乾坤之大千绿帽RPG系统" -Renumber -Apply'
bash 传 PowerShell 数组必须用 -Command '& … -Plan @("A:0","B:43")'； -Plan "a,b" 会被当成单个字符串，脚本里只认到一个元素。

查重（同文异名）

查重.ps1：正文去空白 → 前 120 字聚类快筛 → 组内 5-gram Jaccard ≥ 0.90 判重 → 保留最长，其余移 _重复版本/。

实测抓到 26 份 pixiv 同文多名（《斗罗h》=《淫之舞》、《dzzmcll》=《大主宰洛神后》、《彩潇》=《大主宰之三蛇尊干萧潇》…）。

整本收拢（整合计划驱动）

同一本书常被拆成几十个文件、还有上卷下卷、续集、同名不同版。整合.ps1 按 整合计划.psd1 的 32 族收成「一本一文件」，两条路线：

  • Concat：按 【第X回】/【第X章-】 或文件名 -N- 切段 → 同章取长 → 按章号升序拼接 → 新段前 40 字若在已拼尾部 8000 字内出现就裁掉重叠 → 产物名自动标 起~止（缺X、Y）
  • KeepBest：同书多个完整版，留字数最多那份，其余整份移 _重复版本/整合/
pwsh -NoProfile -File 采集工具\整合.ps1 -Only 斗破        # 预览
pwsh -NoProfile -File 采集工具\整合.ps1 -Apply           # 执行

斗破 152 → 103、斗罗 176 → 147，全库 527 → 447 篇；源单章移 _合并前备份/整合/，逐族流水写 记录/整合记录.csv，明细见项目根的 整合报告.md。

男同筛查（四级）

目标是「有男同内容的都去掉，女同保留」，而且连原文都不留。做法是逐级收窄，最后人工读段：

  1. 男同筛查.ps1 — 每文件词频（Tag / 男性动作 / 女性动作 / 他 / 她 / 肛肠词 / 女性器官词）
  2. 男同摘录.ps1 — 抽男性受体句式上下文，38 份候选
  3. 男同段落.ps1 — 段落内 ≥2 个男名 + 器官词（50 人 roster），55 份 / 220 段
  4. 男同精查.ps1 — 动作词 + 器官词 + 前后不同男名，过滤同名前缀后只剩 4 条
结论：1139 个 txt（校对后 421 + 原文 565 + 合并前备份 125 + 重复版本 28）里没有男 × 男文本。 全部命中都是误判，已分类归档在 男同审计.md。

误判类型：男男女女（人群混处）、龙阳之力（功法名）、同性 指百合、两男名同段但受体是女、「他的菊花」指被女角色指交。
