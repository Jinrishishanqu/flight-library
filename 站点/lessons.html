踩坑记录

按「症状 → 原因 → 修法」写。这些都是实际卡住过、花掉时间的坑，不是理论。

站点反爬

「章节内容加载中…」= 正文在另一个接口

症状 蓝色书吧 /read/<bid>/<cid>.html 的静态 HTML 只有占位符，抓下来是空的。

原因 正文由 reader-async.js（jsjiami 混淆）异步拉取。

修法 用 playwright 拦 XHR 看清真接口：GET /read/<bid>/<cid>.html?ajax=1&_=<ms> + 头 X-Requested-With: XMLHttpRequest，返回正文片段，之后纯 curl 即可，不必开浏览器。

反爬把个别汉字换成 <img data-word>

症状 直接剥标签后正文缺字（「情」消失）。

原因 正文混着 <img class="zi" data-word="&#24773;">，真字在属性里。

修法 先把 data-word 解码回填再删 img。剥离地址广告必须限制在非汉字字符类内，否则「地址发布页.+{0,80}」会把后接正文一起吃成。

PowerShell

变量名大小写不敏感，参数把局部变量覆盖了

症状 脚本报「文本太短，跳过（A=0 B=0）」，明明传了文件。

原因 param([string]$A) 和函数体里 $a = Get-Norm … 是同一个变量。赋值把对象转成了 String，$a.Norm 变空。

修法 param 与局部变量绝不同名：改 -PathA/-PathB + $objA/$objB。同理 $sb（句子）和 $sB（句子数组）也会互相踩，改名 $sentB / $sbr。

"$chars字" 被解析成变量 $chars字

症状 输出文件名变成 《作品》-合集-.txt，字数消失。

原因 中文可以作变量名字符，PowerShell 把 字 吃进了变量名。

修法 用格式化：'{0}字' -f $chars。

单引号字符串里的 \uFEFF 不是转义

症状 首行正则全部失配，整族候选为 0。

原因 文件头有 BOM，读首行时带出 U+FEFF；而 PowerShell 单引号里 '\uFEFF' 是六个字面字符。

修法 $head = (Get-Content -First 1).TrimStart([char]0xFEFF)。

写脚本时正则变成 \\d

症状 所有章号返回 0；-全篇- 判定抢先，整族被当同章去重只剩 1 篇。

原因 落盘时被转义成双反斜杠，在单引号字符串里就是字面两个反斜杠。

修法 文件里必须是单 \d；批量修：sed -i 's/\\\\d/\\d/g' 脚本.ps1。

bash 传数组参数被当字符串

症状 -Paths "a,b" 只有一个元素，只处理了第一个文件。

修法 pwsh -NoProfile -Command '& "脚本.ps1" -Paths @("a","b")'。

文件名含 [] 触发通配符

症状 Get-Content 报文件不存在，但文件明明在。

修法 一律 -LiteralPath。

正则写在 families.psd1 里跑不动

症状 ^\d+-云韵纳兰篇- 在独立测试里 -match 返回 True，放进脚本循环却全部不命中。

绕法 改用语义词表：章节名式用 $head -eq $k，书名式用 $bare.Contains($k)。根因未查明，先绕过去。

泛词（开始 / 处理 / 提议）必须用 -eq，不能用 Contains——否则会误杀《斗破苍穹改编版yin乱的开始枪指萧玉》这类新书章节。

数据处理

校对.ps1 不是增量

症状 重跑一次校对，刚刚合并掉的单章、查重移出的重复件全回来了，篇数从 420 跳回 617。

原因 它从 原文/ 全量重建，而 _合并前备份/ 里只剩 2 个文件，没法反推哪些是已合并源。

修法 建 清理再生.ps1：按 LastWriteTime > -Since 找出新生成的，按「重复件名单 / 已合并源名单 / 关键词表」判再生，移到 _临时/再生件/。以后每次重跑校对，紧接着跑它。

校验报「字符序列不一致，长度相同，首个差异@0」

原因 重建清单时把来源文件按错误顺序拼接（目录枚举顺序 ≠ 章号顺序）。

修法 拼来源必须 Sort-Object { Get-Ch (Split-Path $_ -Leaf) }；全部章号为 0 时改按 文件名长度, 文件名 排（避免「》」与「·」的地域性排序把「续」排到正篇前）。

文件名字数不符（标 2.0w / 应为 2w）

修法 wc 规则必须与校验脚本完全一致：

('{0}w' -f [Math]::Round($chars / 10000.0, 1)).Replace('.0w', 'w')

严格 16-gram 抓不住「改章号的复制正文」

症状 重叠检测只报 31 个 16–24 字碎片，但两份文件明明有整章重复。

原因 复制过来的章节字句有微差，连续 16 字完全相同的位置很少。

修法 换粒度：章对齐.ps1 按章做 3-gram Dice（阈值 0.45），重叠对齐.ps1 按句做（阈值 0.70）。章级最可靠。

关键词筛查分不清「男 × 女肛交」和 BL

原因 器官词、他/她 代词统计、FemN<=1 全部会失真（女名 roster 不全，苏轻吟/戴云儿/王曦/唐心莲 都漏了）。

修法 唯一可靠判据是「同一段内 ≥2 个男性角色名且无女名」，再加人工读段。220 段全部人读过一遍。

外部工具与文件

pwsh 7 加载不了 WinRT，OCR 必须用 powershell.exe 5.1

症状 pwsh -File OCR.ps1 报「找不到类型 [Windows.Media.Ocr.OcrEngine,Windows.Foundation, ContentType=WindowsRuntime]」。

原因 PowerShell 7 跑在 .NET Core 上，没有 WinRT 投影；Windows PowerShell 5.1 才有。

修法 powershell -NoProfile -ExecutionPolicy Bypass -File 采集工具\OCR.ps1 …。可用的识别语言：en-US, zh-Hans-CN（本机）。脚本文件本身要存成 UTF-8 with BOM，否则 PS 5.1 按 ANSI 读，中文全乱。

Edge 无头截图的相对路径不按 cwd 解析

症状 --screenshot="_临时\shot\a.png" 跑完没报错，但工作目录里找不到文件。

修法 传给 Edge 的路径必须先转绝对路径（[System.IO.Path]::GetFullPath()）。同理 --user-data-dir 也用绝对路径。

另：同一 --user-data-dir 若还有残留 msedge 进程，新调用会 attach 到旧实例而不截图——截图前先确认没有残留进程。

WinRT 中文 OCR 会在每两个字之间插空格

症状 一页正文识别出 4368 字，实际只有 2441 字，全是「雳 小 说 一 第 一 版 主 网」这种。

原因 OCR 把每个字/词当独立 token 返回，Line.Text 自带分隔空格。

修法 识别后用正则反复两轮收回空格：(?<=[\u4e00-\u9fff])\s+(?=[\u4e00-\u9fff])，标点两侧同理。另外按 Scale=2.0 放大、按 1800px 切片（重叠 100px）能明显压错字率。

长图一次 OCR 会超限

症状 整页长图（1200×30000）识别失败或只出一半。

修法 [Windows.Media.Ocr.OcrEngine]::MaxImageDimension 是 10000。脚本里按 -SliceHeight 切片，块间留 100px 重叠，再按行去重拼接。

unzip 解不了 WinRAR 的 AES 包

症状 unsupported compression method 99，中文名还乱码。

修法 用 WinRAR 本体（本机无 7z/rar）：

"/c/Program Files/WinRAR/WinRAR.exe" x -o+ -ibck -p"密码" "源.zip" "F:\…\_临时\zd\\"

目标目录用纯 ASCII 绝对路径，源路径加引号。

python 是商店 stub

症状 执行 python script.py 无任何输出，exit 9009 / NOPY。

修法 全部逻辑改用 PowerShell 7。别在 python 上耗时间。

「全本」其实只是第一页

症状 抓下来的章末尾留着 点击[ 数字分页 ]继续阅读-->>【1】【2】【3】【4】【5】【6】，正文只有几千字，但看着像完整一章。

后果 库里一批「1.7w 全本」实际是残页；《斗破苍穹改编版》因此只剩第一章第 1 页。

修法 抓完章节页先解析 chapterPages 里的 /view/<id>_N.html，取最大 N，从第 2 页循环取回再拼。版主爬.ps1 已内置。

代理端口只有一个能用

laowang.vip / vikacg.com 直连 code=000。7897 / 7890 / 7891 / 1080 / 10808 / 2080 / 5283 全不通，只有 127.0.0.1:7899 通（Clash Verge）。

老王论坛：积分不是软妹币

症状 账号积分 1809，点购买报「您的软妹币不足」。

修法 软妹币只能靠每日签到 / 充值攒，跟积分是两套货币。

桌面自动化被 Esc 锁整轮

症状 用户按 Esc 后，screenshot / activate_window / keypress 全部返回 COMPUTER_USE_STOPPED_BY_USER。

修法 该轮不要再试桌面输入，改纯命令行；下一次用户发言后自动恢复。

Python 工具链（v2 引擎）

调 python 必须带 PYTHONIOENCODING=utf-8 PYTHONUTF8=1

症状：脚本里字符串正常，但把中文当命令行参数传进去就 ValueError，或输出在控制台变成问号。
原因：本机 python/python3 是 Microsoft Store 的 stub，真正能用的是 uv 装的 .venv/Scripts/python.exe；Windows 默认 ANSI 代码页会把 argv 里的中文打碎。
修法：PYTHONIOENCODING=utf-8 PYTHONUTF8=1 ./.venv/Scripts/python.exe 脚本.py；中文参数写进脚本文件或用文件传参，别拼命令行。

ftfy 默认会把中文全角标点压成半角

症状：清洗一遍后满篇 萧炎说:"你好"，原本的 ：“” 不见了，diff 显示 6400 处替换 old='：“' new=':"'。
原因：ftfy.fix_text 默认 fix_character_width=True、uncurl_quotes=True，那是给英文语料用的。
修法：ftfy.fix_text(t, fix_character_width=False, uncurl_quotes=False, unescape_html=False, fix_line_breaks=False)。

用 utf-8 读 GBK 原文会让字数虚高 60%

症状：校验报「删除过多」，但打开文件看正文一点没少。
原因：GBK 字节被 utf-8 解码成大量替换符/多字节字符，源字数被算大。
修法：所有源文件都走 decode_bytes()（BOM → charset_normalizer → utf-8 / gb18030 / big5 兜底），别直接 read_text(encoding='utf-8')。

「校验」不能只做「逐字重现」

症状：旧 校验.ps1 要求输出与源逐字一致，于是任何真实清洗都会让它报错，只能验证「没改坏」，验证不了「改好了」。
原因：把「不变」当成了正确性标准。
修法：verify.py 改成两条独立标准——结构合规（BOM / 换行 / 空行 / 字数后缀 / 广告残留 / 半角标点）+ 字数关系（允许 +2% 与 -25% 的清洗空间），二者分开报。

别自己写去广告正则，去抄成熟书源的

症状：手写规则能挡住「请记住本站」，挡不住 最⊥新⊥小⊥说⊥在⊥六⊥9⊥书⊥吧⊥首⊥发！ 这种符号穿插型。
原因：站方专门用穿插符号绕过「整行匹配」。
修法：harvest_filters.py 从 SoNovel 的 31 个书源规则里收割 chapter.filterTxt 得到 59 条正则；再加一条「符号占比 ≥8% 且去符号后命中噪声库 → 整行删」。

MinHash LSH 替代两两比对

症状：查重.ps1 的 5-gram Jaccard 在 500 份文件上要跑十几分钟，增加到几千份就不可用。
修法：datasketch MinHash LSH（num_perm=128、5-shingle、threshold 0.82），先分桶再组内精算；结果仍用 rapidfuzz.partial_ratio 分块验证「100% 被包含」才允许移出。

源文件的换行是 \r\r\n，压空行压不掉

症状：空行压缩规则 \n{3,} 明明在跑，读出来却还是双倍行距；verify.py 报不出裸 LF，因为 \r\r\n 里确实含 \r\n。
原因：源站先做过一次 CRLF→LF→CRLF 的错误转换，留下双 CR。按行拆分再统一写 CRLF 会把它保留下来。
修法：tidy_space 第一步就执行 regex.sub(r"\r\n?|\n", "\n", text)，把三种换行全压成 LF，最后写盘时再统一成 CRLF。筛查：b.count(b"\r\r\n")。

内容层面的判断经验

  • 「同人」这个词在 pixiv 上搜出来的大半不是 H——21% 命中率。
  • tag 命中 + 正文 H 词密度双重判定比单一条件稳。
  • 同一本书在 pixiv 上常有 3–5 个异名版本，前 200 字指纹挡不住，5-gram Jaccard 才挡得住。
  • 回目连载（【第X回）和章节连载（【第X章）要分开建族，混在一起会把两本书并到一处。
  • 跨目录特例：同一本书的章节可能落在两个 IP 目录（《从斗罗开始收取性奴的诸天之旅》第 7 章在「斗破」目录）。
